## 推文讨论的问题

Coding Agent 在写代码之前，需要先找到变化应该发生的位置。推文指出，单纯依赖文本搜索会遇到三类问题：

1. 同一个名称可能出现很多次，Agent 需要逐个打开判断；
2. 相同名称可能代表不同符号或签名；
3. 真正相关的代码可能没有共享查询词，文本搜索会漏掉结构关系。

## 语义代码图的结构

推文把类、方法和接口表示为节点，把 calls、implements 和 extends 等真实关系表示为边；节点与边保留文件和行号。Agent 可以提出结构化问题，例如“哪些类实现了这个接口”，再获得对应位置。

## 本书采用的保守边界

- 代码图提供更直接的结构导航，不等于自动理解所有业务语义；
- 找到所有连接位置不等于修改一定正确；
- 任何修改仍要经过差异检查、构建、测试和 Verifier；
- 推文中的成本数字来自特定研究与任务，本信息图不把它外推为普遍保证。

## 视觉参考用途

用户提供的推文图只作为 A/B 对照、轻手绘卡片和阅读动线的参考。新图必须使用本书自己的中文标题、保守结论和视觉系统，不复制原图品牌、原句或“绝不遗漏”等绝对表述。
