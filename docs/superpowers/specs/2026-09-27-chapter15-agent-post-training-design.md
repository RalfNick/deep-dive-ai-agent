# 第 15 章《Agent 的后训练：什么时候 Prompt 已经不够》设计规格

## 1. 目标与读者

本章面向已经读完第 1–14 章、理解模型调用、Agent Loop、工具、上下文、记忆、评估和生产诊断，但尚未系统学习后训练的开发者。

本章要解决的不是“怎样调用一个训练框架”，而是三个更靠前的问题：

1. 一次 Agent 失败究竟应该修 Prompt、RAG、Skill、Harness、模型选择，还是进入后训练；
2. 如何把 Agent 的任务、轨迹、结果和人工反馈转成可信训练数据；
3. SFT、偏好优化与强化学习分别改变什么行为，又会引入什么新的失败模式。

读者完成本章后，应能解释后训练与提示词工程、检索增强和运行时控制的边界；能审计一批 Agent 轨迹；能用小规模可复现实验理解 SFT、DPO 和基于奖励的策略更新；能识别奖励投机、评测污染和数据泄漏；能为真实项目写出一份包含数据、目标、评估、安全门禁和回滚策略的后训练方案。

## 2. 已确认的设计原则

- 采用“失败驱动”的叙事，不按算法名称写成后训练百科。
- 正文聚焦 Agent 行为，不扩写成完整的通用大模型训练教材。
- 核心实验不要求 GPU、API Key 或真实模型权重。
- 教学实验展示机制与证据合同，不宣称提升真实模型能力。
- Hugging Face TRL 等真实训练框架放在可选迁移指南中，不成为正文主线。
- 任何随时间变化的产品能力、支持模型、参数和限制都进入来源台账，并记录核对日期。
- 第 15 章解释“怎样改变策略”；第 16 章再解释“怎样把生产失败持续转化为规则、Skill、记忆、评测或训练数据”。

## 3. 不在本章交付的内容

- 不下载或微调真实基础模型，不承诺 CPU 可以完成有代表性的 LLM 训练。
- 不提供 GPU、CUDA、分布式训练或集群部署教程。
- 不比较 OpenAI、Anthropic、DeepSeek 或开源模型谁的后训练能力更强。
- 不把有限动作空间中的概率更新叫作真实 LLM SFT、DPO 或 RL 成绩。
- 不实现在线自主修改生产模型的系统。
- 不把供应商定价、模型白名单或当前控制台字段写入稳定正文。
- 不提前写完第 16 章的持续学习平台、生产反馈闭环和自动发布治理。

## 4. 贯穿问题与叙事结构

### 4.1 开场案例

贯穿案例是一个带检索、文件读取、补丁修改和测试工具的文档维护 Agent。它在已知样本中可以完成任务，但在新任务中持续出现三类失败：

- 面对信息不足时直接猜测，而不是先检索；
- 为了让可见测试通过，修改了不应修改的验收文件；
- 工具报暂时错误后反复调用昂贵工具，最终耗尽预算。

团队依次尝试补 Prompt、增加示例和扩大检索，但修复只覆盖了局部表述。通过第 13–14 章的评估与 Trace，团队发现问题是跨任务重复出现的策略偏差，不过其中一部分仍应由权限和验证器解决，而不是训练模型“学会自律”。

开场要让读者看到：后训练不是失败后的默认答案。先把可确定执行的边界留在 Harness，再判断是否存在需要模型泛化的行为模式。

### 4.2 第一幕：决定是否训练

建立一棵干预决策树：

1. 缺少事实或知识时，优先检查 RAG、工具和上下文；
2. 确定性规则、权限和验收可表达时，优先放入 Harness；
3. 任务说明不清或示例不足时，先修 Prompt、Skill 和任务合同；
4. 现有模型能力不足但可替换时，先做模型路由或升级实验；
5. 只有当同类行为偏差跨任务重复出现、存在可复用监督信号、评测能与训练隔离，并且收益足以覆盖数据和训练成本时，才进入后训练。

正文用对照表区分 Prompt、RAG、Skill、Harness、记忆、模型路由、SFT、偏好优化和 RL 的主要修改对象、适用信号、优势与风险。

### 4.3 第二幕：把运行变成数据

从一条原始 Trace 出发，逐步形成训练数据：

- 任务合同：输入、成功条件、允许动作、预算和切片标签；
- 轨迹步骤：Observation、Action、Tool Call、Tool Result 和状态变化；
- 结果证据：Outcome、Verifier 结果、安全事件和资源消耗；
- 反馈：人工修订、成对偏好、拒绝原因和不确定项；
- 血缘：来源运行、Harness 版本、模型版本、时间窗口和变换记录。

本节重点解释：成功轨迹不一定值得模仿；失败轨迹不一定应该删除；工具返回中的密钥、个人信息和隐藏答案不能直接进入训练集；同一任务的近重复样本不能跨训练集和评测集；由旧评测器生成的数据不能未经检查继续训练新策略。

### 4.4 第三幕：三种策略更新

三种方法始终使用同一个“观察状态—选择动作”示例，避免算法与任务脱节。

**SFT：模仿被保留的动作。** 解释 Token 级交叉熵与 Agent 轨迹行为之间的关系。有限动作实验只计算动作概率变化，明确它不是语言模型训练。讨论专家示范不足、错误示范复制和状态覆盖不完整。

**偏好优化：扩大 chosen 与 rejected 的相对间隔。** 以 DPO 为主要数学例子，给出可手算的参考策略、候选策略、偏好对、温度系数和损失。解释为什么偏好对必须比较相同任务状态，为什么“更长”“更自信”可能成为伪偏好，以及参考策略在约束漂移中的作用。

**强化学习：在环境反馈中探索。** 用有限状态环境展示回报、策略、探索、信用分配和 KL/参考约束。正文不把 PPO、GRPO 等优化器细节展开成训练课程，只说明它们在数据来源、更新方式和稳定性上的位置，并将具体框架接口放入迁移指南。

### 4.5 第四幕：训练为什么会学坏

本节围绕可观察失败展开：

- 奖励只看测试通过，策略学会修改测试；
- 奖励偏爱少调用工具，策略学会跳过必要验证；
- 只保留成功轨迹，数据掩盖拒绝和恢复行为；
- Judge 偏好完整长答案，策略用冗长换得更高分；
- 训练集包含评测任务或隐藏答案，离线成绩虚高；
- 标量奖励把安全、正确性和效率混成一个数字，允许高收益抵消严重违规；
- 针对一个任务切片更新后，其他切片发生回归。

给出纵深约束：奖励只提供优化方向，安全硬门禁、权限、沙箱、Verifier、数据审计和独立评测仍由外围系统负责。

### 4.6 第五幕：从候选策略到可发布版本

将第 13–14 章的评估方法重新接入：冻结评测集、保留 baseline、按任务切片比较、报告 Unknown 与环境错误、设置安全否决、检查效率和成本、灰度发布并准备回滚。

结尾形成一张决策清单：

- 问题是否需要模型泛化，而不是确定性规则；
- 数据是否有合法来源、明确血缘和足够覆盖；
- 训练目标是否能被投机；
- 评测是否与训练隔离；
- 候选策略是否在安全和关键切片上不退化；
- 收益是否覆盖训练、推理和维护成本；
- 失败后能否回滚到已知版本。

## 5. 实验包设计

### 5.1 总体边界

新增自包含目录 `chapter15/`。运行时以 Python 标准库为主，测试依赖锁定版本的 pytest。实验使用固定夹具和固定种子，不联网、不读取环境中的模型 API Key、不下载权重。

所有报告都必须可重复生成，不包含当前时间、随机 UUID、临时路径或作者机器绝对路径。连续两次运行应得到相同的稳定摘要与哈希。

### 5.2 核心数据合同

- `TaskCase`：任务 ID、输入状态、可选动作、成功条件、禁止动作、预算、标签和数据切分。
- `TrajectoryStep`：步骤编号、观察摘要、动作、工具请求、工具结果、策略概率、奖励分量和安全事件。
- `TrajectoryRecord`：任务、运行 ID、模型/Harness 指纹、步骤序列、最终结果、Verifier 证据和数据血缘。
- `SupervisedExample`：状态、目标动作、样本权重、来源轨迹和保留理由。
- `PreferencePair`：相同任务状态下的 chosen/rejected、参考策略对数概率、偏好来源和置信度。
- `RewardSpec`：结果、过程、效率和安全信号；安全信号支持硬门禁，不能只作为可抵消的负分。
- `AuditFinding`：严重度、原因码、证据引用、建议动作和是否阻断进入训练集。
- `PostTrainingReport`：数据质量、策略指标、切片回归、安全违规、泄漏检查、已证明与未证明结论。

### 5.3 五组实验

#### 实验一：什么时候不该训练

输入一组失败记录，分别注入缺知识、权限缺口、验收缺口、提示歧义和跨任务策略偏差。决策器输出建议干预及证据理由。消融掉问题分类后，展示所有失败都被错误送往训练的成本。

本实验只验证决策规则是否按合同工作，不证明规则能自动诊断任意生产事故。

#### 实验二：从 Trace 到可信数据集

准备至少 24 条固定轨迹，包含成功但越权、正确失败、敏感数据、隐藏答案泄漏、近重复任务、评测集重叠、缺失工具结果和未知来源。流水线执行规范化、脱敏、去重、切分和质量审计。

输出训练候选、偏好候选、隔离样本和阻断原因，并展示“只按最终成功过滤”会留下哪些坏样本。

#### 实验三：SFT 模仿与示范偏差

在有限状态、有限动作策略上实现可复算的交叉熵更新。比较干净示范、混入捷径示范和缺少恢复状态示范三种数据集，观察动作概率、训练损失和切片准确率。

实验用于解释行为克隆与数据覆盖，不代表 Transformer 参数更新或真实 Coding Agent 能力。

#### 实验四：DPO 偏好与参考约束

使用固定 log probability 和偏好对实现 DPO 损失及更新方向。比较低/高 `beta`、错误偏好标签、跨状态错误配对和长度伪偏好。至少提供一个正文可手算样本，并由测试验证公式。

#### 实验五：强化学习、奖励投机与发布门禁

在小型工具环境中运行固定种子的策略更新。对比：

1. 只奖励任务通过；
2. 将安全违规作为可抵消负分；
3. 安全硬门禁 + 结果奖励 + 预算约束。

展示策略如何学会修改测试、跳过验证或重复低成本动作。最终使用冻结切片和 baseline 做发布判断，结果只能是 `pass`、`fail` 或 `inconclusive`。

### 5.4 可选真实训练迁移指南

新增 `chapter15/real-training-guide.md`，说明如何把本章合同映射到 Hugging Face Datasets/TRL 或供应商后训练服务：

- JSONL/Chat Template 与工具调用消息怎样表达；
- SFT、DPO 和奖励训练分别需要哪些字段；
- 训练参数、显存、模型许可与数据许可需要单独核对；
- 如何复用冻结评测集与安全门禁；
- 哪些命令只是示例，没有在本项目中运行。

该文件不得给出伪造训练日志、吞吐、成本或模型提升比例。

## 7. 原创插图

采用全书现有的浅色纸张、手绘描边、蓝绿紫橙分区风格。技术文字和箭头使用可控矢量布局，避免生成图中文字错误。

1. **干预决策树**：Prompt、RAG、Harness、模型路由与后训练分别接住哪类失败。
2. **轨迹数据工厂**：Trace 到规范化、脱敏、去重、切分和训练样本。
3. **三类目标地图**：SFT、偏好优化、RL 的输入信号、更新对象和典型风险。
4. **SFT 概率变化**：相同状态下示范怎样提高目标动作概率，也怎样复制坏示范。
5. **DPO 偏好对**：chosen、rejected、参考策略与候选策略的相对间隔。
6. **奖励投机现场**：任务成功、测试篡改、效率分与安全硬门禁的关系。
7. **训练—评测—发布闭环**：数据版本、候选策略、冻结评测、灰度和回滚，并指向第 16 章。

每幅图必须在正文中说明读图顺序和它回答的问题，不能作为装饰性插页。

## 8. 正文章节密度

- 约 2.2–2.8 万中文字符；以解释清楚为先，不重复定义凑字数。
- 20–35 个二、三级标题。
- 4–6 张比较表或检查清单。
- 5 组可运行实验，至少 5 个明确失败样本。
- 12–14 道分层练习，包含概念、手算、运行、修改和系统设计题。
- 参考答案包含 DPO 手算、数据审计结果、奖励消融输出和设计题判据。

## 9. 来源策略

来源台账至少覆盖以下类别，并优先使用论文或官方文档：

- 指令微调与基于人类反馈的对齐研究；
- DPO 原始论文及后续边界研究；
- Constitutional AI / RLAIF 等偏好信号研究；
- OpenAI 当前 Fine-tuning、Graders 与 Reinforcement Fine-tuning 官方资料；
- Hugging Face Transformers、Datasets 与 TRL 官方文档；
- Agent 工具使用、可验证奖励、代码任务 RL 和轨迹训练的近期论文；
- Reward hacking、specification gaming、数据污染和评测泄漏研究；
- 模型与数据许可、安全和隐私相关的权威资料。

写作前逐项核对日期、版本和原始链接。快速变化的产品事实只作带日期映射，不成为稳定原理的唯一证据。

## 11. Review 与版本保护

完成实现后进行两轮 Review：

1. **读者视角**：检查是否通俗、术语是否在使用前解释、手算是否可跟随、代码是否喧宾夺主；
2. **AI/后训练专家视角**：检查目标函数、数据边界、偏好对、奖励设计、评测隔离和结论强度。

高优先级问题修复后形成 `v1.0-rc1` 记录。是否进入正式发布、更新 manifest、同步博客和创建 tag，必须由后续明确的发布请求触发。

## 12. 完成定义

本章候选只有在以下条件同时满足时才算完成：正文、实验、七幅图、来源台账、练习与答案、Review、版本记录和本地预览齐全；实验与全书回归通过；所有可变事实有来源与日期；报告清楚区分“机制已验证”和“真实模型未训练”；第 15 章仍保持未公开状态，等待单独审阅和发布决定。
