日期：2026-09-28。状态：章节组织方式已获用户确认；本设计稿待审阅，尚未进入实施计划或书稿实现。执行方式沿用此前确认的 native。

本地分支：`codex/chapter16-continuous-improvement`。基线：第 15 章 RC2 提交 `2bcfaf0250fdd8dbf8b1f051bc62d576bef52875`。本章只形成新的本地候选，不推动第 15、16 章发布。

## 1. 目标、读者与成功标准

读者已经理解 Agent Loop、上下文、记忆、工具、评估、Trace 和后训练，但还不知道如何把一次次真实失败变成可维护的改进资产。

本章的核心问题是：**Agent 已经被纠正过，为什么还会犯同样的错误？怎样把一次失败变成下一次真正有效的改进？**

全章的短答案是：不是把投诉、聊天记录或模型反思直接写进长期指令，而是建立“发现—取证—回放—归因—提出变更—验证—审批—受控启用—观察与回滚”的闭环。一次任务内的自我修正、跨任务的经验记忆、系统版本更新和模型权重训练，是四种不同的改变。

读者完成后，应能：

1. 区分反馈、失败证据、原因假设、经验、改进提案和生效版本。
2. 将一条失败整理成可回放案例，说明冻结了什么、还缺什么。
3. 判断应修改知识、Prompt、Skill、Harness、记忆还是训练数据，而不是默认追加永久规则。
4. 在实验中看到改进资产实际改变后续决策，同时观察过度泛化、租户串扰和失效。
5. 为候选变更建立独立回归、审批、版本绑定、灰度观察和回滚条件。
6. 解释反馈污染、评测污染、规则堆积和自我强化为何会让系统越改越差。

写作目标为约 1.8 万至 2.5 万正文汉字，30–36 个二三级标题、7 幅原创图、5 张比较表、5 组实验、至少 5 个明确失败样本和 13 道分层练习。篇幅统计分别列出正文叙述汉字与包含英文、代码、Markdown 的总字符数；不能用总字符数冒充中文篇幅。讲清问题优先，不重复免责声明或同义表述凑数。

## 3. 已确认的叙事方案

采用“短案例＋独立反例”。读者先跟着一条小失败走通闭环，后续每一节用最能解释该机制的反例，不强迫全书或整章所有实验使用同一个业务任务。

另外两种方案不作为主线：

- 全程延续 Coding Agent 修复仓库：执行感强，但会重复第 12、15 章的修复与测试案例。
- 从零搭持续学习平台：组件覆盖广，但接口、Schema 和部署容易遮住学习目的。

开场使用虚构的“Atlas 应用帮助中心”：用户询问项目导出操作，Agent 引用了旧版帮助文档；用户纠正它，当前回复改对了，下一次新会话却继续犯错。资料中的产品、规则、租户和用户均为教学夹具，不影射真实公司政策。

先展示三种修复的不同后果：

1. 只修当前答案，下次运行仍走旧决策路径。
2. 把“总选最新文档”写成全局指令，误用于历史版本问题或其他租户。
3. 留下失败证据、生成有适用条件的变更、保护旧行为，再通过审批启用。

第三种并非天然正确，后续实验必须真实验证它，而不是由叙述宣布成功。

## 4. 正文结构与阅读节奏

正文保留已确认的十四节骨架，三级标题细化到约 30–36 个。前半章先讲人能复述的小问题，后半章再展示完整数据合同。

### 第一幕：纠正过，不等于学会

1. 被纠正过，不等于已经学会：走完上述短案例。
2. 本次任务调整、跨任务记忆与系统版本更新：指出实际改变了哪个对象，谁会受影响，什么时候恢复。
3. 从投诉到证据：用户反馈并非客观金标；区分主观偏好、可核验事实、错误反馈、重复报告与恶意指令。

引入概念时先给自然语言例子。Trace、反馈原文、错误原因和修复建议不能合并成一个“经验”字段。

### 第二幕：从症状走到可验证的变更

4. 失败回放：冻结任务输入、文档版本、工具结果、权限、时钟与 Agent 版本；区分读取旧 Trace、回放固定工具结果和重新运行真实模型。
5. 归因：同样的错误答案可能来自旧知识、错误检索、流程遗漏、权限设置或工具故障；用一次只替换一个条件的小实验提供条件性反证，不宣称真实生产因果证明。
6. 把失败转成回归样本：保留输入、独立成功条件、来源与用途；不能把原错误答案当成验收目标。
7. 改进载体：知识、Prompt、Skill、Harness、记忆与训练样本；按事实、行为、确定性边界、个体偏好和跨任务策略分别选载体。

临时服务故障需要止血、重试或基础设施修复，不应自动沉淀成永久用户记忆。证据不足时保留 Unknown，不强行归因。

### 第三幕：从建议走到受控启用

8. 候选变更：范围、来源、所有者、版本、前置条件与失效条件；把“我总结了一条规则”与“这条规则已经生效”分开。
9. 验证改进：目标问题复现、原通过行为保护、任务切片与安全不变量；发现集、开发回归与留出验收的用途不得混用。
10. 人工审批、离线灰度演练与回滚：审批绑定变更和证据；审批后改内容、文档真值变化或证据过期，都必须重新验证。回滚激活指针不等于撤销已经产生的外部副作用。

不展开统计推导或平台 API。指标、状态表和完整 Schema 放在实验包、报告与进阶材料，正文只保留理解机制必需的字段。

### 第四幕：防止改进系统自己学坏

11. 反馈污染、过度泛化与评测集自我污染：拒绝绕过审批、取消验证、跨租户扩散和访问隐藏答案。
12. 系统也会遗忘：适用范围、时间条件、撤销许可、规则冲突、过期与清理；旧经验不能压过当前权威事实。
13. Reflexion、Self-Refine、GEPA 的位置与限制：分别解释单任务迭代、反思记忆与提示搜索；不把它们统一称为权重训练，也不照搬论文收益。
14. 小结、13 道分层练习和下一章衔接：明确本章证明及未证明事项，连接图像、语音、屏幕任务中的新证据与新回放限制。

代码只承担观察机制的角色，不能让读者必须先读完数百行实现才能理解该节。

### 5.1 十二条失败/反馈记录

| ID | 现象 | 应保留的判断边界 |
| --- | --- | --- |
| F01 | 权威修订指出当前问题引用旧文档 | 可以提出有时间与任务范围的目录规则修订 |
| F02 | 同一失败的重复反馈 | 合并血缘，不当作两份独立证据 |

| F05 | 结构化输出缺少必须字段 | 先提任务合同/Prompt 候选；不声称已经训练模型 |
| F06 | 重试流程重复产生写入提议 | 提 Harness 修复，不把幂等责任交给记忆 |
| F07 | 反馈要求取消审批或跳过验证 | 隔离攻击反馈，不提升为指令或 Skill |
| F08 | 用户 A 希望回答更简短 | 只可提出限定租户、用户和有效期的偏好记忆 |
| F09 | 布尔标记为 false，但载荷含已知演示敏感模式 | 窄规则检测仍隔离，脱敏不得清除来源敏感证据 |
| F10 | 缺工具回执，无法判断执行结果 | 回放与归因为 Unknown，不补造成功证据 |

F01/F03/F08 是三类可执行候选的来源；其他记录用于去重、阻断、Unknown 或只产出提案。不同来源不能只用一个 `trusted=true` 放行，必须同时验证范围、完整性、许可与成功条件。

### 5.2 文档与回归任务

夹具含 6 份虚构帮助文档，覆盖当前/历史版本、租户 A/B 和步骤说明。任务集含 16 项，分为 knowledge（知识）、procedure（步骤）、scope（作用域）和 safety_recovery（安全与恢复）四个教学切片，每片 4 项。

其中每片 1 项为开发回归、3 项为留出验收，总计 4+12。开发回归可以复现来源反馈中的失败，但开发回归与留出验收使用不同 task family；相同 family 不跨这两种用途。发现反馈也标记来源用途，隐藏验收反馈不得成为生成候选的输入。

baseline 与 candidate 必须在同一冻结真值、文档、作用域和时钟下比较。权威事实发生变化时，旧证据失效，建立新的套件版本并重新比较；不得改写旧金标来挽救候选，旧报告仍按原合同保留。

运行 Agent 只接收任务输入与可访问文档，不接收任务期望输出；期望输出只由评分器读取。候选不能按 task ID、数组下标或隐藏期望字段硬编码答案。夹具作者事先知道样本，留出集合只演示工程隔离，不构成盲测真实模型泛化。

三种比较对象分别标明：baseline、显式不安全的盲目吸收控制组、有作用域的 candidate。不安全控制只在内存夹具中演示失败，不能修改真实用户指令或运行环境权限。

## 6. 最小架构与数据合同

处理链：FeedbackRecord → admission/ReplayCase → LessonProposal → ArtifactRevision → EvidenceBundle → ApprovalReceipt → ReleaseRecord → 观察/回滚。

每个模块只负责一层，不直接耦合第 13–15 章的内部类。前章报告仅通过可选只读适配说明映射稳定语义，默认实验不依赖前章实验包。

| 合同 | 必须表达的内容 |
| --- | --- |
| FeedbackRecord | ID、来源角色与用途、tenant/user、任务与运行引用、反馈载荷、原始敏感证据、完整性、许可与冲突线索 |
| ReplayCase | 输入、文档/工具结果/权限/Agent 快照、时间、成功条件引用、任务 family、回放支持程度与缺失项 |
| LessonProposal | 来源反馈、原因假设与证据、目标载体、适用条件、建议变更、不确定项与不能泛化的范围 |
| ArtifactRevision | 知识规则/Skill/记忆等类型、父版本、内容、scope、owner、有效期、来源引用和内容哈希 |
| EvidenceBundle | baseline/candidate 与套件/真值/环境/安全合同指纹、逐任务结果、切片、违规、Unknown、门禁及证据哈希 |
| ApprovalReceipt | 审批者与决定、候选及证据哈希、允许范围、有效期；与候选自身内容分开 |
| ReleaseRecord | 父/当前激活版本、审批引用、离线灰度分配、停止原因、回滚目标与回执；不是公开网站发布记录 |
| ImprovementReport | 五组实验、准入与原因码、回放覆盖、变更与验收证据、激活历史、失败清单、证据限制与 Schema 版本 |

模块职责拟定为：`contracts.py` 数据合同，`feedback.py` 准入与去重，`replay.py` 固定输入/工具结果回放，`lessons.py` 有限候选生成，`artifacts.py` 版本及作用域，`agent.py` 消费实验资产，`evaluation.py` 独立评分，`governance.py` 审批与激活/回滚，`experiments.py` 稳定报告入口。

知识选择规则、步骤型 Skill、用户偏好记忆必须真正被 `agent.py` 消费，实际改变选择/步骤/格式决策，而不只是生成一段 Markdown。Skill 是有限步骤解释器与人类可读说明的对应示例，不执行任意代码、Shell 或 `eval`，也不安装到真实 Claude Code/Codex。

Prompt、Harness、训练数据只输出有血缘的提案或样本候选，不在激活器中伪装成已支持资产；激活不支持的类型必须拒绝。候选样本导出不读取 eval 答案，不承诺符合某个训练 Provider 的格式。

## 7. 五组实验与可观察结果

### 实验 16-1：反馈盲信为什么会污染系统

将十二条记录分别送入盲目吸收控制和准入管道，输出接受/隔离/合并/Unknown 及原因。注入 F07/F09/F12，观察取消验证、未标记敏感模式和隐藏答案被挡在资产生成之前。脱敏后再入库也不能“洗白”。此实验不声称检测所有注入或个人信息。

### 实验 16-2：读 Trace 不等于回放成功

重现 F01 的旧文档选择，并逐项替换文档选择条件与步骤条件；比较同一症状的不同假设。F04 标为环境故障，F10 标为回放不完整；不能重放的案例不得参与“修复成功率”分母，同时必须另报“可回放数/总案例数”的覆盖率和各类缺失数量，Unknown 仍阻断激活，不能静默排除来抬高成绩。重用固定工具结果不会真实调用外部工具，也不证明重现了随机模型的完整轨迹。

### 实验 16-3：经验放在哪里，决定它会影响谁

从 F01/F03/F08 产生三类有作用域的资产，并使后续决策实际变化。对照“全局总选最新文档”和“所有用户都简短回答”的过度泛化变体，验证历史版本问题、租户 B、另一位用户与过期记忆仍保持原有合同。打印匹配条件、资产版本和实际应用记录。

### 实验 16-4：修好一个问题，不等于可以启用

冻结候选后运行开发回归及留出验收，打印逐任务变化和安全否决。负例覆盖目标问题仍失败、新回归、安全越界、Unknown、环境错误、缺切片覆盖。拿到通过证据后改候选内容、套件/文档真值/权限快照或用过期证据，再演示审批失效。人工审批由可信测试夹具提供，不能由候选自己写 `approved=true`。

### 实验 16-5：离线灰度、漂移与回滚

用固定种子与 task ID 计算稳定哈希并排序，前 4 个试运行请求分给候选，其余 12 个保留基线；保存 cohort 分配表以便复查。分配不是在真实生产流量上做随机试验，也不用于估计真实 A/B 因果收益。模拟新版本出现步骤回归或 scope 越界，停止候选并恢复已知基线指针，打印激活与回滚回执。推进时钟检查记忆过期；旧资产内容虽留档，过期或撤销许可的资产不能因回滚再次生效。

## 8. 门禁、失败语义与安全边界

评测决策为 `pass / fail / inconclusive`，仅说明本地教学候选是否满足激活合同，不授权真实部署。

判定顺序固定：

1. 明确安全越界、隐藏答案使用、验收篡改或未经授权的全局扩散，直接 fail，不能由平均分抵消。
2. 无硬失败但回放不完整、环境错误、Unknown、缺覆盖或证据指纹不匹配，inconclusive，禁止激活。
3. 目标开发回归必须由失败变通过；任一基线原通过任务变失败，或任一验收切片下降，fail。
4. 所有前置证据有效且合同满足才 pass；pass 之后仍需要独立、未过期、范围匹配的审批回执。

具体发生率必须给分母；重复反馈不扩大证据数；步骤与调用计数不叫 Token 或费用。阈值是 16 项确定性教学集的合同，不是生产统计显著性或安全认证。

安全要求：

- 准入先检测已知敏感键/模式、脱敏并保留来源标记；精确布尔类型、血缘、用途、scope、许可和完整性都要检查。
- 未受信任反馈、反思和工具文本只作为数据，不能提升为系统指令或突破权限。
- 记忆限定 tenant/user/domain，具备到期、撤销与来源；用户偏好不能覆盖安全、事实和业务硬约束。
- 审批绑定候选与评测证据哈希；底层数据/环境/安全合同变化使旧证据失效。夹具审批不是密码学认证或生产授权系统。
- 同一证据只允许一次有效激活；重复尝试不得重复追加副作用。回滚保持历史，不删除经验来源、报告或旧版本。
- 文件输出只能落在本工程的指定运行目录，拒绝路径越界与危险链接；默认拒绝覆盖已有报告，不提供破坏性的 `--replace`。
- 本地激活仅变更实验内的资产快照/指针；不提交生产配置、发消息、改用户记忆、启动定时任务、安装插件、训练模型或部署网站。
