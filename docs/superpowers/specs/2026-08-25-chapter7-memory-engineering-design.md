# 第 7 章“记忆”设计说明

状态：已由作者于 2026-08-25 确认。

## 目标

第 7 章回答一个具体问题：当前任务结束后，哪些信息值得被未来独立任务复用，以及系统怎样可靠地写入、召回、修正和遗忘这些信息。

本章采用“从零构建”的教学路径。读者先看到一个忘记用户偏好的最小 Agent，再逐步加入结构化记录、写入闸门、召回排序、冲突修正、删除与隔离。每增加一个概念，都必须先由前一个版本的可观察失败引出。

## 范围边界

- 第 5 章负责单次调用前的 Context 装配；
- 第 6 章负责当前长任务的 Session、RunState、Checkpoint 与压缩；
- 第 7 章只处理跨任务复用的长期 Memory；
- 第 8 章再深入文档切分、Embedding、向量检索、混合召回、重排和 RAG 评估。

因此，第 7 章可以提供检索接口和确定性关键词实现，但不把向量数据库或 RAG 管线提前写完。

## 贯穿案例

贯穿案例是一名持续协作的 Coding Agent。用户先后表达：

1. 以后代码示例优先使用 Python；
2. 修改公共 API 前必须先确认；
3. 某次临时排障允许跳过一个慢测试；
4. 后来把偏好改为优先使用 TypeScript；
5. 最终要求删除个人偏好。

这个案例能同时暴露遗忘、历史噪声、一次性授权被长期化、旧偏好冲突、删除不完整和跨项目串线。

## 教学顺序

1. `v0`：无记忆，未来任务完全忘记；
2. `v1`：回放完整聊天，信息存在但噪声与生命周期混杂；
3. `v2`：引入带类型、作用域和来源的 `MemoryRecord`；
4. `v3`：加入 Write Gate，拒绝猜测、Secret、一次性授权和低价值内容；
5. `v4`：加入 Recall Pipeline，先作用域硬过滤，再按任务相关性、权威、时效和置信度排序；
6. `v5`：加入 Correct 与 Forget，使用新版本和 Tombstone 保留审计链；
7. `v6`：加入租户隔离、Trace 和分层评估。

正文坚持“现象 → 最小代码 → 中间结果 → 原理 → 失败边界”的循环。框架和产品映射放在原理与实验之后。

## 核心数据模型

`MemoryRecord` 至少包含：

- `memory_id`：不可变逻辑标识；
- `namespace`：租户、用户、项目和 Agent 作用域；
- `memory_type`：semantic、episodic、procedural；
- `subject`、`content`：记录对象与内容；
- `source`、`authority`：来源与权威；
- `confidence`：只表示记录生成方的把握，不替代验证；
- `valid_from`、`expires_at`：有效期；
- `sensitivity`：敏感级别；
- `version`、`supersedes`、`status`：修正与删除链；
- `created_at`：由确定性时钟注入，固定实验不使用当前系统时间。

系统不把用户画像设计成第四种底层存储。画像是从当前有效的语义记忆中投影得到的可编辑视图。

## 四个核心操作

### Write

原始对话先产生 `MemoryCandidate`，再经过作用域、来源、敏感信息、生命周期、价值和冲突检查。模型只能提议写入，Store 才能提交。

### Recall

召回先做 namespace、状态、权限和有效期硬过滤，再做相关性排序。模型只能看到经过选择的投影，并同时得到来源、类型和更新时间。

### Correct

修正不静默覆盖旧记录。新记录通过 `supersedes` 指向旧版本；旧版本转为 superseded，便于解释过去为何召回了旧值。

### Forget

逻辑遗忘先写 Tombstone，阻止缓存或索引把旧内容重新带回；物理删除由受控清理流程完成，并输出不包含原文的删除收据。

## 实验合同

所有规范实验默认无 API Key、固定输入、固定时钟、固定排序和稳定 JSON 序列化。

1. 无记忆、完整历史、结构化记忆三组对照；
2. Write Gate：稳定偏好、猜测、Secret、一次性授权和重复候选；
3. Recall：Top-K、噪声、作用域、时效和权威消融；
4. Correct：冲突偏好、过期事实、并发版本和 Tombstone；
5. Isolation：跨租户、跨项目、删除后召回和索引陈旧故障。

报告分别输出：任务验收、写入精确率、写入召回率、召回精确率、过期使用数、重复有效记录数、修正收敛、删除后泄漏数和跨作用域泄漏数。没有证据的指标使用 `null`，不合并成单一总分。
