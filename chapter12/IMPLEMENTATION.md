## 实施调整记录

- 使用现有独立书籍克隆及新实现分支隔离工作，没有让书籍代码进入学习工程的 Git 历史；风险：交付时需核对并快进同步到指定书籍目录。
- 技能辅助脚本显式使用 Git Bash coreutils 路径；风险：环境不同需调整脚本调用，不影响书籍运行时。
- venv 使用仓库惯用的 `.venv` 名称，避免安全扫描遍历第三方包；不放宽扫描规则。风险：环境需按锁重建。
- pip-tools 核心解析完成后，框架解析延迟；统一改用 uv 0.11.15 生成 universal/hash 锁并据此安装。风险：解析器差异需要重新锁定，不能混用未经验证的版本。
- 统一 diff 使用宿主私有基线与标准库生成，不调用候选 Git 配置或 hook。风险：不支持 Git 高级 rename 检测，正文必须明确范围。
- 只指定读取起始行时，默认读取从该行起的 200 行，而非固定到第 200 行；风险：默认窗口变化，但字节上限不变。
- 动作意图保存完整前后文件清单；所有调用（不只写操作）检查 call_id 冲突；正式 action_id 在入账时绑定 run_id。风险：记录稍大，后续调用者必须使用持久化返回的 action_id。
- 字数、来源格式等写作检查作为编辑审计而非行为单测；风险：完成时必须逐项人工记录，不能以代码测试替代阅读审稿。

以上调整不删除真实模型、容器、Pi 源码参照或两套框架重构的原定交付。
