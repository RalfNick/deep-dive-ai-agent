# 第 13 章练习参考答案

这些答案不只给结论，还说明“结论依赖什么证据”。第 2、7、8、10、11 题直接调用本章实现；其余设计题输出结构化验收标准。先从仓库根目录运行：

```powershell
.\.venv\Scripts\Activate.ps1
python -B -m chapter13.exercise_solutions --all
```

运行单题使用 `--number 3`。若要保存机器可检查结果，可添加 `--output chapter13/reports/exercise-results.json`；目标已存在时命令返回 3，不会覆盖旧证据。

## 1. Final Answer、Outcome 与 Trajectory

- Final Answer 是 Agent 的声明，例如“退款已完成”。
- Outcome 是独立观察到的环境终态，例如支付平台存在一笔 100 元退款。
- Trajectory 是到达终态的事件链，例如查询订单、请求批准、调用退款、读取回执。

反例：Agent 最终退款成功，但先重复扣款再回滚。Final Answer 正确，Outcome 可能最终正确，Trajectory 仍不可接受。三类证据不能互相替代。

## 2. 同一句完成声明背后的证据

机器答案会实际运行实验 13-1。两条 Trial 的 `final_answer` 相同，但应重点比较：

1. `solution_matches`：实现是否真正满足独立验收；
2. `protected_paths_intact`：受保护测试是否保持不变；
3. `events`：是否发生策略违规、写入与验证。

因此 `same_final_answer=true` 只说明两个系统生成了同一句文本，不能推出它们具有相同 Outcome，更不能推出它们都合规完成任务。

## 3. 手算 pass@1、pass@3 与 pass^3

给定 `n=5`、`c=2`、`k=3`：

```text
pass@1 = c / n = 2 / 5 = 0.4
pass@3 = 1 - C(3,3) / C(5,3) = 1 - 1/10 = 0.9
pass^3 = C(2,3) / C(5,3) = 0
```

`pass@3=0.9` 表示从五次样本中取三次时，至少一次成功的组合估计；`pass^3=0` 表示只有两次成功，不可能取出三次全部成功。二者没有矛盾，回答的是相反的可靠性问题。

## 4. 替换一个 basic 任务

可将一个 basic 任务替换为 `basic-mailto-link`：检查器跳过 `mailto:user@example.com`，但仍报告缺失的本地 `missing.md`。成功条件必须同时包含正例与负例；允许写入 `src/`，保护 `tests/` 和 `.eval/`。

“保持切片平衡”意味着替换原有 basic 题，而不是追加第 13 题。否则切片权重变化，总体分数将无法与旧报告直接比较。

## 5. 环境错误还是 Agent 失败

| 现象 | 默认分类 | 还需核对的事实 |
| --- | --- | --- |
| 评测方依赖源下载失败 | `environment_error` | 网络和依赖源是否由评测方保证 |
| Agent 耗尽步骤预算 | `agent_failed` | 预算合同是否在运行前固定 |
| 测试进程 OOM | 待归因，不先写 `Trial.status` | 资源保证是否相同、负载是否由 Agent 制造；查明后归为 `environment_error` 或 `agent_failed` |
| 模型返回非法工具参数 | `agent_failed` | schema 和解析器版本是否正常 |

分类不是看错误消息中的关键词，而是判断故障由谁控制。如果 Candidate 的行为稳定触发 OOM，而 Baseline 不会，就不能一律归为环境免责。这里的“待归因”不是 `Trial.status`；只有某个 Grader 的证据不足时，才返回 verdict=`unknown`。

## 6. “发送退款”的轨迹不变量

可使用三条与具体工具顺序无关的不变量：

1. 任何真实退款前，必须存在绑定同一订单、金额和当前状态的有效批准；
2. 同一 `refund_id` 最多产生一个成功副作用回执；
3. 宣布完成前，必须从支付方读取终态，并确认退款金额与目标一致。

Agent 可以选择不同查询或校验工具，只要不变量成立。要求固定成“必须先调用 A 再 B 再 C”容易误伤同样安全但更短的合法路径。

## 7. Outcome 通过而 Safety 失败

参考脚本构造 `pass_1=1.0`、效率通过，但 `safety_violations=1` 的 Candidate。`release_decision()` 返回：

```json
{"decision":"fail","reasons":["safety_violation"]}
```

效率是软指标，安全是硬门禁。将二者加权平均，会允许“更快地越权”抵消违规，这与安全约束的产品语义冲突。

## 8. 总体提升但安全切片下降

总体提高 5%，安全切片下降 12%。本章门禁规定任一切片下降超过 0.10 即失败，因此结论是 `fail / slice_regression`。下一步不是调整平均权重，而是定位安全切片的失败 Trial，修复后用同一批 Task、种子和环境成对重跑。

如果切片下降恰好为 0.10，当前代码使用“小于 -0.10”作为失败条件；阈值边界必须在配置和版本记录中保持一致。

## 9. 选择 pass@k 还是 pass^k

- 代码候选生成：若允许生成多个候选再由可靠测试选择，关注 `pass@k`。
- 自动退款：每次都产生真实副作用，关注 `pass^k`。
- 研究报告：编辑从多个草稿中选择时用 `pass@k`；自动连续发布时用 `pass^k`。
- 批量文件重命名：批处理中的每次失败都可能破坏工作区，关注 `pass^k`。

指标由产品如何消费结果决定，不由任务名称决定。只要存在可靠选择器，“至少一个好候选”才有意义；不能选择或每次都必须正确时，应衡量持续成功。

## 10. 成对 Bootstrap

参考实现提供 12 个有正有负的任务级差值，并固定种子 `20260924` 做 10,000 次重采样。平均差为 `1.67%`，95% 区间为 `[-5.83%, 9.17%]`，所以返回 `inconclusive`。关键点有三项：

1. 先对同一 Task 的 Baseline 与 Candidate 求差；
2. 以 Task 为重采样单位，不把同题五次 Trial 当作五道独立题；
3. 区间跨零时返回 `inconclusive`，不宣称 Candidate 更强。

增加 Bootstrap 迭代次数只减少数值模拟误差，不能让 12 道缺乏代表性的题突然变得有代表性。

## 11. Judge 校准与混淆方向

规范夹具的总体一致率为 66.67%，预测 `Unknown` 比例为 33.33%。需要同时读混淆矩阵，而不是只看一致率。参考脚本实际调整 `j07` 与 `j12` 的预测标签，保持命中总数不变，却改变不同金标行中的错误流向；它会输出调整前后的矩阵，而不是只复述预置标签。

对自动退款、医疗建议或权限审批，`gold=fail, predicted=pass` 通常更危险；对低风险内容排序，过多假阴性可能更伤产品覆盖。危险方向由业务后果决定，不能从一个总体准确率推导。

## 12. 防止评测投机

- 隐藏测试：放在被测进程不可读、只由外部 Grader 挂载的位置；
- Oracle：答案和凭据不进入 Agent 工作区，访问由外部策略记录；
- Git 历史：从净化快照创建任务，移除泄漏修复内容的提交和远端；
- 跨 Trial 缓存：每次使用新工作区与命名空间，并校验初始环境指纹。

目录命名为 `.eval` 不是安全控制。本章教学工作区会创建该目录以展示违规轨迹，但不声称它能抵抗主动恶意代码。

## 13. 映射 Inspect AI

一种合理映射是：

| 本章抽象 | Inspect AI |
| --- | --- |
| `TaskSpec` | Task 与 Dataset sample |
| Runner / 策略适配 | Solver |
| Graders | Scorer |
| Report | Eval log 与 metrics |

框架不会替业务团队决定三件事：任务是否代表真实需求、安全不变量是什么、怎样的回归值得阻止发布。产品 API 可以替换，责任边界不能外包。

## 14. 评估评估器

建议按以下顺序调查：

1. 复现环境并核对指纹、依赖和资源；同夹具健康后再排除环境；
2. 请两位领域人员独立完成并复核 Task；对成功条件一致后再排除题目歧义；
3. 用人工金标、反例和历史样本校准 Grader；测量误差在预定阈值内再排除评分漂移；
4. 固定 Task、种子、Harness 与环境，成对重跑 Agent 版本；稳定的剩余差值才归因给 Agent 变更。

每一步的停止标准都是“存在可复现记录”，不是“看起来没问题”。只要证据冲突，最终发布状态就应保持 `inconclusive`，等待补充证据或人工决策。
