# 第 11 章练习参考答案

对应 [正文](../book/chapter11.md) 的 14 题。答案关注可观察依据，不要求与作者采用相同措辞。所有动手修改仅在 chapter11.prepare 创建的可信教学目录进行，不操作业务仓库。

## 1. 相对路径的起点

正确过程：docs/api/reference.md → 所在目录 docs/api/ → docs/api/../guide/start.md → docs/guide/start.md。

错误过程：仓库根目录 → ../guide/start.md → 仓库父目录下的 guide/start.md。它可能误报，也可能误命中仓库外同名文件；“错误路径一定不存在”是不成立的。

## 2. 三个绿灯为什么不够

旧测试覆盖根目录文档、真正缺失文件、外部链接跳过，没有覆盖子目录链接。新增回归在旧实现失败，说明它能区分目标错误；修复后同一测试通过，才形成有意义的前后对照。红绿对照仍不证明所有 Markdown 语法或所有路径场景正确。

## 3. 确认活动入口

方法一：读测试的 import，再沿导入路径确认 linkcheck.py。方法二：在教学目录使用 Python 查看导入模块的 __file__，并核对实际运行命令和工作目录。也可以从应用入口沿调用链追踪。

搜索排序只反映工具排序；legacy/ 中同名实现可能完全不参与运行。在同名模块较多的项目，静态阅读与实际导入位置应交叉验证。

## 4. 六行内任务说明

> 目标：修复嵌套文档中相对文件链接被误报的问题。<br>
> 输入：docs/guide/start.md 中的 ../faq.md，应指向 docs/faq.md。<br>
> 约束：不改接口、legacy/、notes.txt 或无关文件。<br>
> 先增加能复现问题的回归测试，再修改活动源码。<br>
> 从教学仓库根目录运行 python -m unittest discover -s tests -v。<br>
> 交付失败到通过的结果、测试数量、最终 diff 和已知限制；不提交或推送。

## 5. 三种不同职责

AGENTS.md 保存本项目约定，例如活动源码位置、运行目录和测试命令。Skill 保存可复用的任务方法，例如“复现—回归—修复—验证”的材料和步骤。Hook 在产品支持的指定事件上执行动作，例如在工具调用后记录结果。

文件不是自动强制执行机制。Hook 是否能阻断、如何返回、什么时候触发都取决于事件合同；一个 Git 提交 Hook 也不能自动替代 Agent 的工具调用事件。

## 6. 手动红绿修复

先运行 prepare，进入生成的目录。记录 git status --short；运行三个旧测试，保留命令与结果。在 tests/test_links.py 的 LinkTests 类中追加：

```python
    def test_nested_document(self):
        self.assertEqual([], broken_links(ROOT, ROOT / "docs/guide/start.md"))
```

再运行原命令：4 项测试，其中新增测试失败。现在把 linkcheck.py 的 base = root 改为 base = document.parent，重新运行，预期 4 项通过。最后查看 git diff -- linkcheck.py tests/test_links.py。

可用 python -m chapter11.quickstart 对照固定程序的同一过程。若手动输出不同，不修改报告来迎合预期；先核对活动文件、缩进、运行目录和是否真的执行了新增测试。

## 7. 用户笔记与过期补丁

只修改 notes.txt 不改变 linkcheck.py 的摘要。使用正确源码摘要应用一行补丁后，笔记应逐字节保留。

第二种场景先记录 linkcheck.py 摘要，再追加一行协作者注释；使用旧摘要调用 patch_file 应抛出 stale_source，当前源码与笔记都不变。对应可执行断言是 test_fix_passes_acceptance_and_keeps_user_notes 和 test_stale_patch_is_rejected_and_current_edit_survives。

整仓证据摘要与源码补丁摘要用途不同：笔记变化会让旧整仓验收失效，却不应自动阻止一个只依赖当前源码版本的补丁。检查后仍有并发窗口；该测试不提供多人写锁保证。

## 8. 零项测试

运行 verification 组，查看 zero_tests：tests.exit_code=0、tests.count=0、accepted=false。退出码表明测试运行器没有报告失败，不表明发现了测试；本工作台还拒绝错误范围 empty_tests。因此不能将“命令成功”“测试充分”“任务完成”合并成一个布尔值。

## 9. 新增真正缺失的嵌套链接

在 docs/guide/start.md 添加 一个显示文字为 Missing、目标为 ../absent.md 的内联链接，且不要创建 docs/absent.md。新的期望 missing 列表应为 ["../absent.md"]，有效的 ../faq.md 不在其中。

这次需求变化同时影响 REGRESSION 的嵌套检查和独立 ACCEPTANCE 中 nested_valid 的预期；不能只改测试，却保留“整个文档无缺失链接”的旧验收。建议在实验包副本新增一个独立场景：先声明新预期，再生成夹具、增加断言、冻结测试，最后修复路径。

旧代码通常报告 ["../faq.md", "../absent.md"]，正确代码只报告 ["../absent.md"]。同时保留根目录 missing.md 的负样本，拒绝把 broken_links 改成无条件 return []。新增场景另存报告，不覆盖本章规范五组结果。

## 10. 文档变化使证据失效

修复后调用 verify 保存 receipt；随后在 docs/faq.md 追加普通说明；调用 evidence_is_current(root, receipt) 应为 false。它不会把旧 receipt 的 accepted 改为 false，而是判断该历史证据能否代表当前文件状态。

整仓摘要简单、保守，能防止遗漏文档等相关变化；代价是无关笔记或措辞修改也会触发失效。可按验收依赖收窄集合，但需要证明集合完整，不能为了减少重测而静默漏掉输入。

## 11. 结束事件检查程序

输入应包含明确工作目录、任务 ID、预先审阅的验收基线标识和待交付版本。基线不能每次从刚被修改的测试目录重新生成，否则“冻结”失去意义。

程序运行预定测试与独立样本，记录命令、测试数、退出状态、工作区摘要、测试摘要、开始结束及超时信息。输出区分 pass、fail、environment_error、timeout。事件返回值需要转换为目标产品支持的结构，不能假定所有事件都允许阻断。

给检查设总预算，超时返回未通过；不无限重试。Hook 被禁用、未触发或结果未被消费时，应显示“未验收”，并由独立 CI 或人工门禁补足。Hook 不是唯一可信来源，仓库本身可能修改检查程序。

## 12. 只读子任务

> 调查其他相对文件路径是否也从仓库根目录出发。仅阅读和搜索，不修改、不执行仓库脚本、不联网。区分活动实现与历史示例。每项发现返回文件、行号、输入例子、调用依据、置信度和未确认点。

主 Agent 应核对引用位置、活动调用链与例子的输入语义，必要时自行构造回归。没有发现不等于不存在；只读也是权限配置要落实的限制，不能只靠提示词。主 Agent 保留最终修改与验收责任。本题是设计练习，书稿没有伪称已经启动子 Agent。

## 13. 产品观察实验

固定夹具、初始状态、任务文本、验收与人工介入规则。记录产品/模型版本、系统、启动目录、权限、工具、指令加载证据、每次介入、源码测试 diff、命令输出和计时范围。为每次运行使用新的独立目录。

某产品遇到权限问题时不偷偷给它更多权限；如需调整，作为另一轮条件并记录。单次任务不能推出通用能力、生产可靠性、成本优势或模型排名。更多细节见 [产品观察指南](product-walkthrough.md)。

## 14. 文件相同也不一定等价

本章 fingerprint 只覆盖文件，不覆盖解释器版本、依赖、环境变量、网络、服务端数据、系统时钟和硬件。文件未变只支持“这个文件快照仍相同”，不支持运行环境不变。

扩展证据可加入 Python 版本、依赖锁摘要、容器镜像 digest、允许公开的配置摘要，以及外部数据版本或有效期；不能把原始密钥写进报告。对不可固定的服务状态重新验证，或明确旧证据适用的时间和范围。
