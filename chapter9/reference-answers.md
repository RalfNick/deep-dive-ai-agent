# 第 9 章练习参考答案

参考答案给出判断路径，不是唯一实现。每题先看控制权和信任边界，再看代码形式。

## 第 1 题

**推理：** `current_runbook()` 的主要用途是读取由应用选择的参考材料，没有副作用，因此保持 Resource 能清楚表达“应用取数据，模型消费数据”。只有当用户明确委托模型自主决定是否检索，且检索本身需要参数、审计或独立授权时，才适合改成只读 Tool。

**常见错误：** 按返回值是不是字符串分类；认为只读能力一定是 Resource；忽略分类改变会把选择权从 Host 或用户转给模型。

**验收：** 答案同时说明谁选择、怎样调用、是否有副作用、Host 怎样展示，并给出一个保持 Resource 的理由和一个改成 Tool 的条件。

## 第 2 题

**推理：** 在 `properties` 中加入 `include_dependencies: {"type":"boolean","default":false}`，不加入 `required`，并保留 `additionalProperties: false`。有效断言应接受布尔值 `true`；无效断言应在 `/include_dependencies` 给出 `type` 问题并拒绝字符串。

**常见错误：** 把字段加入 `required` 破坏旧调用；在 Handler 中用字符串真假值转换；删除 `additionalProperties: false`。

**验收：** 旧参数仍通过，布尔值通过，字符串被 Schema 门拒绝，Handler 无需知道兼容逻辑。

## 第 3 题

**推理：** JSON Pointer 应包含数组下标，例如第二个对象缺少字段时路径形如 `/evidence/1/id`，关键字为 `required`；第一个对象的 `id` 若要求字符串，则 `/evidence/0/id` 对应 `type`。稳定排序让相同输入产生相同反馈，便于快照、回归和模型定向修正。

**常见错误：** 只报告顶层 `evidence`；用自然语言位置替代机器可解析路径；依赖字典遍历偶然顺序。

**验收：** 列出所有问题的路径与关键字，并能用指定测试核对；若实现顺序不同，解释为什么需要规范排序。

## 第 4 题

**推理：** 建立 `pending_by_call_id` 映射，逐个 Result 按 ID 取回请求并标记完成。未知 ID 是协议关联错误，重复 ID 是重复结果或重放，结束时仍未匹配的是缺失结果。`step_id` 表示循环阶段，一个步骤可包含多个调用，不能唯一标识调用。

**常见错误：** 使用数组下标或返回顺序；把重复结果覆盖掉；认为同一步只能有一个 Tool Call。

**验收：** 算法在结果逆序时仍正确，并为未知、重复、缺失三种情况给出显式状态。

## 第 5 题

**推理：** 缺少字段是 `invalid_arguments`；没有 P1 Scope 是 `denied`；服务不存在是 `business_error`；未预期驱动异常是 `execution_error`。前两类在条件不变时不应自动重试，业务错误是否重试由原因码决定，执行异常需结合副作用与幂等性。模型看到可行动的稳定码，受保护日志保存异常关联和内部诊断。

**常见错误：** 所有异常重试三次；把堆栈直接返回模型；把“找不到记录”和程序崩溃混为一类。

**验收：** 四类映射完整，分别写明重试、模型可见信息和受保护日志，且没有泄露内部秘密。

## 第 6 题

**推理：** 确认卡应展示 Server 身份、Tool、P1、标题、证据 ID、预计创建一张外部工单。确认结果由 Host 写入受信 Caller Context，模型 Arguments 只保留业务参数，不能包含 `approved`、角色或凭据。拒绝、超时、Server 无 Scope 分别代表用户决策、未得到决策和组织授权失败。

**常见错误：** 用户点击后向 Arguments 加 `approved=true`；有 Scope 就跳过确认；把三种拒绝都写成 `permission denied`。

**验收：** UI 字段齐全，信任信息不由模型控制，三种失败有独立原因码和恢复路径。

## 第 7 题

**推理：** 额外的 `receipt` 字段必须因封闭 Schema 被拒绝，否则调用者可能污染可信证据。Receipt 至少包含 Action ID、Call ID、Tool、参数摘要、外部 ID 和发生时间。摘要证明所执行参数的指纹，外部 ID 提供查询锚点，时间只证明执行器记录的时刻；三者都不能单独证明业务正确。当前 Receipt 由 Runtime 根据受信 Handler 的成功响应构造，不是外部系统的密码学签名。响应丢失还需要持久幂等账本或外部按键查询，关键动作还可按外部 ID 回查或验证签名。

**常见错误：** 让 Handler 忽略伪造字段；由模型生成外部 ID；认为有 Receipt 就证明工单内容正确。

**验收：** 六个字段完整，三个字段的证明边界清楚，并指出内存实现无法覆盖进程退出后的未知结果。

## 第 8 题

**推理：** 查询库存和执行退款通常是 Tool；产品手册与数据库表结构通常是 Resource；排障模板和生成周报的用户模板通常是 Prompt。若查询库存被应用固定展示为页面数据，可建模为 Resource；若只读内容需由模型决定何时按复杂参数查询，也可使用 Tool。

**常见错误：** 以“是否返回文本”分类；把 Prompt 当系统提示；认为 Resource 永远无需授权。

**验收：** 六项均说明选择者、副作用和授权；任何非典型分类都给出产品控制权依据。

## 第 9 题

**推理：** Host 错在信任未验证的只读声明并跳过同意；Client 若丢失 Server 身份、annotation 或策略信息，也破坏了连接责任；Server 错在错误描述能力并用过高权限执行。修复包括可信 Server 清单与版本固定、危险动作确认、Server 业务授权、低权限运行身份、命名空间和审计回执。

**常见错误：** 只怪模型或协议；认为 `readOnlyHint` 是安全证明；让 Client 替 Server 做最终业务授权。

**验收：** 三层责任分别陈述，至少四个修复覆盖 UI、元数据、业务授权、运行身份和审计中的四类。

## 第 10 题

**推理：** 现代路径让请求携带所需版本和能力描述，可选 `server/discover`，不要求先建立持久初始化会话；旧路径先初始化再调用。`mode="legacy"` 只证明锁定 SDK 的显式兼容路径。是否降级取决于 Server 信任、缺失语义、迁移期限和风险：本地低风险可告警降级，受管环境可用兼容代理，高风险且语义缺失时拒绝。

**常见错误：** 把 `server/discover` 当强制握手；无提示自动降级；从一个进程内测试推出所有实现互通。

**验收：** 两条时序清楚，准确说明发现与初始化的区别，并给出带条件的兼容决策。

## 第 11 题

**推理：** 本机仓库读取适合 stdio，进程边界清晰且无需网络；公司内网共享事件系统适合 Streamable HTTP，需要统一身份、部署和网络策略；同进程数学函数直接调用最简单。MCP 的价值来自跨进程或跨客户端复用，不是给每个函数增加协议层。

**常见错误：** 全部远程化；忽略 stdio 子进程也需要文件权限；用网络传输解决同进程函数。

**验收：** 三项选择不同且分别讨论信任、部署、身份、网络、延迟和运维成本。

## 第 12 题

**推理：** Tool 描述、Resource 内容和 Tool Result 都是不可信输入，进入 Host 后可能影响模型的下一次提议。防护应组合 Server 来源验证、隔离运行、网络 allowlist、数据与指令分层、结果过滤、敏感动作二次授权和最小化日志。即使如此，获准数据仍可能通过获准通道泄露，这是剩余风险。

**常见错误：** 只写“加强 Prompt”；把合法 JSON 当可信内容；日志中原样保存秘密以便复盘。

**验收：** 数据流标出三个不可信入口，至少六道防护落在具体边界，并明确一项无法完全消除的风险。

## 第 13 题

**推理：** 当前单一 Web 应用可用 Provider Function Calling 加本地 Runtime 调稳定报销 API；Skill 保存领域流程与使用说明，应用负责分发。未来 IDE、桌面端和多个 Host 需要复用时，再把稳定能力暴露为 MCP Server；插件解决安装、权限声明与组合分发。迁移时保留同一领域服务，只新增 Adapter，避免业务逻辑复制。

**常见错误：** 一开始同时引入所有层；把 Skill 当执行安全边界；认为插件和 MCP 是同义词。

**验收：** 两阶段架构、复杂度成本、触发 MCP 的条件和可复用迁移路径均明确。

## 第 14 题

**推理：** 先建立按领域、风险、Scope 和版本过滤的 Tool Catalog；模型只获得搜索 Tool，Host 根据搜索结果按需加载少量 Definition。执行层保存 Run、Step、Call 与 Action 状态，后台任务具有排队、运行、取消请求、超时、完成和未知结果等状态，并使用持久幂等键。指标至少包括发现命中率、加载数、参数拒绝率、授权拒绝率、调用延迟、重复副作用、取消成功率和未知结果数。

**常见错误：** 三百个描述全部塞入上下文；搜索结果绕过权限裁剪；取消只停止前端等待；用进程内字典保存幂等键。

**验收：** 图中包含搜索、裁剪、加载、提议、校验、授权、执行和回传；状态覆盖后台任务与恢复；列出至少六个可计算指标。
