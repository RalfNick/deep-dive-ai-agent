# 第 4 章双视角 Review

Review 日期：2026-08-12。对象：`book/chapter4.md`、`chapter4/` 实验、边界故障矩阵、`chapter4-review-codex.md` 与预览 PDF。

## 普通读者视角

### 结论

章节保留了最直观的 21 节学习路径：从“同一个模型为何像换了一个 Agent”进入，依次看到上下文、工具、权限、沙箱、状态、恢复、幂等、故障语义、验证和 Trace，最后再映射 Claude Code 与 Codex。贯穿实验始终固定决策策略，只替换外围 Harness，读者能够把抽象边界对应到可运行结果，而不必先申请 API Key。

### 发现与处理

| 优先级 | 发现 | 处理 |
| --- | --- | --- |
| P1 | 若把对照组写成“裸 Loop”，会与第 3 章已有超时、验收和 Trace 的实现冲突 | 改为“能闭环的内联 Loop”：它不是没有循环，而是权限、状态、执行和验证仍耦合在一个控制流中 |
| P1 | 21 个主题容易提前写完第 5、6、9、10、13、14 章 | 本章统一回答“谁负责、接口怎样连接、失败后进入什么状态”；内部算法和优化明确留到后续章节 |
| P2 | 上下文压缩、幂等、Trace 等术语对初学者密度较高 | 每节都先给失败现场，再给最小合同、实验结果和一句边界判断；复杂实现用“本章到哪里为止”收束 |
| P2 | 18 道正文练习会破坏收尾节奏 | 正文保留 15 道分层练习，另列 3 道扩展实验，并提供对应参考答案 |
| P2 | 单案例使用 0.0/1.0 容易被误读为统计率 | 改为 `true/false/—` 并显式记录 `sample_count=1` |

## AI 工程专家视角

### 结论

章节正确地区分了模型决策、Agent Loop、运行时 Harness 与更广义的仓库/产品 Harness；也区分了策略判断与沙箱强制、模型宣布完成与外部 Verifier 验收、Trace 结构完整与完成证据完整。实验只能证明确定性边界合同，没有把结果包装成模型能力或 Claude Code/Codex 排名。

### 发现与处理

| 优先级 | 发现 | 处理 |
| --- | --- | --- |
| P1 | 初版所谓“消融”由不同任务轨迹组成，不符合严格单变量定义 | 改名为“边界故障实验矩阵”，正文逐行说明独立案例，不再暗示横向效率比较 |
| P1 | Trace 结构评分与完成审计曾混在一句话中 | 明确 `grade_trace()` 只检查因果结果和审批前检查点；完成状态是否同时有 Verifier 证据由独立审计负责 |
| P1 | 示例中的状态摘要哈希与真实运行不一致 | 重新执行完整 Harness，并把三处示例统一为真实摘要 `77c5226d3d08f7f5` |
| P2 | 审批恢复演示把“恢复前写入数”硬编码为 0 | 改为读取执行环境的真实计数，防止演示输出掩盖回归 |
| P2 | “先保存检查点、再请求审批”不足以证明跨系统原子性 | 明确本地实验只验证进程内顺序；生产系统仍需要事务型 outbox、消息去重或等价机制 |
| P2 | 幂等账本不能覆盖外部副作用已发生但回执未落盘的未知结果 | 正文把 exactly-once 限定为业务协议问题，并将 reconciliation/补偿列入扩展实验 |

## 未被本章证明的事项

- 未比较真实模型的规划、编码或工具选择能力，也未对 Claude Code、Codex 或 SDK 排名；
- 未覆盖真实并发、分布式事务、跨主机崩溃恢复和外部审批系统的消息投递保证；
- 教学 `WorkspacePathGuard` 只演示路径边界，不等于操作系统级容器、网络隔离或完整供应链防护；
- 确定性成本单位不是真实 Token 价格，不能据此估算生产账单；
- Verifier 和 Trace 证明的是本实验合同，不等于用户意图、安全与业务正确性的完整证明。
