# 第 17 章 RC3：读者与技术一致性复核

日期：2026-10-01。范围：[当前正文](../chapter17.md)、配套实验、参考答案、资料台账与七图。本轮是作者侧实施与复核，没有另派独立审稿者，也不是新模型盲评。RC2 基线为 `4d96603`，原版本记录和审稿不改写；历史保护及完整命令见[RC3 修订记录](../versions/chapter17-v1.0-rc3.md)。

## 结论

上一轮五项建议均已落实。主线仍是“看见 → 核验 → 授权行动 → 实时事件与证据链”，没有强迫图表、屏幕、语音共用一个业务故事，也没有扩大为真实 OCR、桌面控制或音频服务教程。建议作为**本地 RC3 候选**保留；不得把离线教学结果包装成真实模型评测或生产验收。

## 读者视角

| 问题 | RC3 处理与检查 |
| --- | --- |
| 开头同时切换图表与 UI，认知负担偏高 | 先给两根柱子和一个增长率问题；截图、语音在各自幕中重新建立问题，不要求读者记住同一故事 |
| 不易判断“运行后到底看到什么” | 组 1/4 给明确标为精简摘录的真实 JSON；组 3 给可运行的四行摘要；先读字段，再解释结论，未伪称终端会直接打印这些 JSON |
| 工程名词先出现，解释靠读者自行拼接 | 观察合同、血缘、归约首次出现先用“保存什么、如何追溯、如何由事件计算状态”解释；给两个可运行短片段，两个内部摘录明确不是独立程序 |
| 局限声明多次打断叙事 | 合并开场与若干重复提醒，关键机制附近仍保留局限；不为了流畅而删掉安全、权限与证据边界 |
| 练习语义与实现可能不同 | 17-10 保留原序号与重新编号分别计算；另补生成取消确认替换为请求时的预期，正文、答案和可运行解答一致 |

尚存取舍：后半章的状态合同比一般产品介绍更密，适合按幕阅读；固定绘图格式不具有真实视觉的覆盖面。保留 20,634 个叙述汉字是为了讲清机制，并不以字数证明可读性或内容质量。桌面/手机七图、五表均可阅读，没有整页横向溢出。

## 技术专家视角

| 发现 | 修复证据 | 仍然不能外推的结论 |
| --- | --- | --- |
| 解析几何不等于读到可见内容 | 七个隐藏/裁切/遮挡用例修复前失败；固定 viewport、柱体着色、元素数与画布内坐标检查后通过 | 这只是窄输入语法，不是通用 SVG 渲染器，也未证明所有文字和图形在任意环境都可见 |
| 生成取消确认被写成请求/停播 | 两个回归测试区分 `response_cancel_requested`、`response_cancelled` 和 `playback_stopped`；状态增加 `generation`，图 17-6 标签同步 | 中性事件名不是官方协议字段，未知初始生成状态不代表真实设备状态；后台取消另需自己的确认 |
| 派生语音事件与原文件摘要不相符 | 三个参数化测试从各自输入文件校验 SHA-256，并重新归约状态；组 4 报告保存 `event_source` | 摘要只证明使用了哪些输入字节，不能证明真实时间戳、说话者身份或网络完整性 |
| 文中结果可能只是作者写出的示意 | 两个完整片段实际执行；两个 JSON 逐字段对照规范报告；四种屏幕摘要与当前运行器一致 | 片段通过不代表所有未来输入正确；执行回执仍是模拟器，不是业务后端提交回执 |
| 版本覆盖会丢失可审计历史 | 14 份 RC2 冻结文件与 Git 字节一致；原 RC1/RC2 18 份报告、旧记录和公开 manifest 保留 | 快照不是独立运行包，复现旧完整实验应使用旧冻结提交 |
