## 首次读者视角

关键路径部分现在先保留 `80 + max(120, 200) + 40` 的直观手算，再用真实夹具补上 35 ms 观测缺口。读者能够同时理解三件事：并行 Span 不能相加、最长工作链可以指导优化、最长工作链仍不等于端点耗时。

采样部分不再用一句“先脱敏再采样”覆盖所有时机。图 14-6 将 Head 与完整载荷分成两条路径：Head 只读取 Trace ID；Tail 只能读取安全 Trace。这个改动保留了初学者能记住的简单规则，也避免专家读者把实现误解为 Head 必须等待完整 Trace。

事故报告部分增加了明确的降级规则：没有反证时不能声称 `confirmed`。这比只在练习答案中提醒更可靠，因为读者运行代码时也会得到相同约束。

## Agent 与可观测性专家视角

### 关键路径语义

`work-dag-longest-path.v1` 仍按依赖 DAG 累加已插桩工作 Span，不改变 rc1 的 p50/p95 结果。新增未归因时间只是 `endpoint - observed work path`，用于暴露排队、调度或插桩缺口，不被命名为 queue time，也不用于直接证明根因。

### Incident Report 证据门禁

领域对象和 JSON Schema 使用相同条件约束：只有 `conclusion=confirmed` 时，支持证据与反证才强制 `minItems=1`。`inconclusive` 可以保留空证据列表，但必须通过 Unknown 说明下一步需要什么数据。规范事故报告本来就包含三条支持 Trace 和四条反证 Trace，因此结论与既有实验数值不变。

### Sampling 与隐私时序

Head 的确定性桶只消费 `trace_id`，可以在完整事件形成前执行。Tail、缓冲、Export 和 Store 属于载荷路径，必须消费已脱敏并通过安全门禁的 Trace。总体请求数与最终失败数仍在采样前独立聚合，Tail 保留集合仍不作为总体分母。

## 已知限制

- 未归因时间只说明当前关键工作链没有覆盖全部端点时间，不会自动识别排队、网络、调度或插桩缺口各占多少。
- “必须有反证”是本章为教学诊断合同选择的严格规则；真实组织可以使用更细的证据类型，但不能把“没有寻找反证”伪装成“没有反证”。
- Head/Tail 实现仍是进程内确定性夹具，没有评估 Collector 的缓冲容量、背压和跨进程丢失。
- 72 条 Trace、教学成本单位和固定消融仍不代表真实生产分布、供应商能力或现实因果发现。
- 本轮沿用 rc1 的双视角自审方式，没有引入独立第二审稿人。

## 最终判断

rc2 已消除本轮审查发现的两个重要口径缺口和一个采样时序歧义。关键术语现在能从正文追溯到字段、代码、Schema、测试和配图，不存在“文章要求更严格、公开合同却允许绕过”的断层。适合冻结为新的本地候选，但仍不授权推送、发布或加入公开导航。
