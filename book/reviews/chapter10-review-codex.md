## 读者视角

- 开头用订单助手工具菜单变大、报表请求变长建立两个问题；没有从名词清单开始。
- 先手算 3 分/2 分，再解释搜索和加载；先让用户重复点击，再引入提交键；先让旧 worker 回来，再解释租约与代次。
- 两个场景独立，不强行拼接目录夹具和报表处理函数。正文明确统一 `record_id` 只是定义载荷夹具，报表代码实际参数是 `month`。
- 六幅图沿用米白手绘风格；图 10-3 首轮误导性逐行箭头已改为组间总箭头，图 10-1 已移除误印的布局说明。两张修订图已重新目检。
- 正文约 2 万中文字符，32 个二三级标题，4 张比较表；14 题有计算答案、可运行测试和设计判据。不是靠重复免责声明凑篇幅。

## 工程与事实核查

| 问题或风险 | 处置与证据 |
| --- | --- |
| 按需路径只统计最终 Schema，容易夸大缩减 | 报告计入 150 字节入口、452 字节摘要、810 字节定义；总计 1,412，明确非 Token |
| 简单 split 可能被误称为中文语义检索 | 正文说明空格关键词合同；无匹配返回空，平分不冒充消歧 |
| 只有内存顺序调用，无法证明持久领取互斥 | 补两个独立 SQLite 连接、屏障竞争同一租约的真实测试 |
| 结果写入后、状态写入失败的中间窗口 | 用 SQLite trigger 注入事务异常，验证结果记录回滚且可随后成功提交 |
| 只拦截旧代次，漏掉过期但尚未重领的 worker | 分别测试 stale_attempt 与 lease_expired |
| 把取消请求当作已经停止 | 分开 queued 取消、running 请求取消、提交前确认、提交后保持成功，以及过期取消回收 |
| Windows 报告生成器默认写 CRLF | 先加入 LF 断言重现失败，再显式固定 UTF-8/LF；不削弱测试 |
| 预览相对资源路径多退了一层 | 将测试从字符串匹配改为真实目标可达检查，先重现失败，再修正为两层父目录 |
| 平台资料快变，旧样例可能误导 | 以官方资料重新核对延迟加载、Background mode、MCP Tasks 扩展；不固定模型下限与旧字段 |
| 本地唯一回执被误读为外部 exactly-once | 正文用邮件已发出、本地未落账反例，明确需要对方幂等或查询/对账 |

## 保留的限制

无真实模型、无 MCP Tasks/供应商 SDK 集成、无 HTTP 服务、无登录鉴权、无自动 worker 调度/续租、无外部副作用。逻辑时间由测试提供，连接重开不是断电恢复测试。状态与结果读取检查 owner，但调用方身份本身必须可信。有限并发输入仍是内存列表，不支持无限流量。图 10-4 是常见路径示意，完整转移以代码为准。

## 后续可加强，但不混入本章已证实结论

工具发现仍是确定性关键词夹具；可在单独 Live 评测中观察真实模型查询生成和参数选择。后台作业可继续接入真实队列、外部服务幂等与长时间负载，但这些不应通过增加几条模拟报告就标成已完成。正式发布时重新核对提供方与 MCP 扩展文档，并由其他读者试跑一次从零环境。
