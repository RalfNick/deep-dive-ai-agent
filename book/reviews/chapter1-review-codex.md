## 总体结论

第一章的选题、主问题和总体结构是合理的，已经具备正式书稿的骨架，建议判定为**条件通过**。

章节从“只预测下一个 Token，为什么看起来却很聪明”这一矛盾切入，依次建立模型与 Agent 的边界，解释下一 Token 训练、Token、Embedding、Transformer、自回归生成、能力来源与模型边界，再用 Coding Agent 验证循环收束。这个顺序与全书“模型怎样逐步变成 Agent”的主线一致，不建议大幅重排。

当前主要问题不是章节缺内容，而是三处论证口径需要收紧：

1. 结尾声称“本章证明了模型能够在上下文中产生有用的下一步”，但五个实验没有调用真实神经语言模型；
2. 开头声称 `parse_price()` 是贯穿全章的同一任务，但前四个实验并没有真正使用这条任务数据；
3. 残差连接段落把梯度传播方向写反了。

综合评价约为 **8.0/10**。修复 P1 问题、补齐实验记录与最小回归测试后，可以进入复审稿。

## P1：必须修改

### 1. 结尾对实验结论存在过度外推

正文写道：

> 本章证明了模型能够在上下文中产生有用的下一步……

位置：`book/chapter1.md:1157`。

但五个实验分别是：

- 真实 Tokenizer；
- 手工构造的注意力矩阵；
- 基于计数的字符 Bigram；
- 固定 Logit 的分类采样；
- 使用固定补丁的确定性 Coding Agent 模拟。

其中没有实验调用真实神经语言模型，也没有测量模型能否根据 `parse_price()` 上下文提出有用补丁。`coding_agent_demo.py:3` 和正文 `book/chapter1.md:990` 已经正确承认这一点，因此小结反而扩大了证据范围。

#### 建议修改

优先保持本章“无 API Key、隔离机制”的教学定位，直接收紧结论，例如：

> 本章用 Tokenizer、玩具注意力、字符 Bigram、采样实验和确定性 Agent 模拟，展示了从文本表示到下一步选择的关键机制，以及模型提议与外部执行的系统边界。它没有评测真实 LLM 是否会为给定任务产生正确下一步，也没有证明任何模型已经达到生产可用水平。

如果确实想保留“证明模型能产生有用下一步”，就必须增加真实模型实验，并记录模型版本、提示、采样配置、多次运行结果、成功标准与失败样本。对第一章而言，这会引入不必要的变量，建议采用收紧结论的方案。

### 2. “同一个任务贯穿全章”与实际实验不一致

开头承诺：

> 我们会依次观察这个请求怎样被分词、怎样进入注意力计算、怎样形成工具调用，又怎样通过测试获得外部证据。

位置：`book/chapter1.md:9`。

实际情况是：

- Tokenizer 默认样本是“深入浅出 AI Agent”等通用文本；
- 注意力实验使用三个匿名二维向量；
- 采样实验使用“读取、调用、删除”三个玩具标签；
- Bigram 使用一段 Agent 通用语料；
- 只有第五个实验和章末案例真正使用 `parse_price("￥19.90")`。

所以 `parse_price()` 目前是开头和结尾的“概念路标”，还不是贯穿实验的同一条可重放轨迹。

#### 建议修改

两种方案都可行：

**方案 A：真正贯穿。**

- 在 Token 实验中增加 `让 parse_price("￥19.90") 返回 19.9` 固定样本；
- 给注意力实验中的三个位置命名为“任务、实现、失败测试”，明确这仍只是表示示意；
- 将采样标签改为与任务相关的候选下一步，如“读取实现、修改文件、运行测试”；
- 在实验记录中用统一任务 ID 串联输入、模型提议、Harness 动作和验证结果。

**方案 B：降低承诺。**

把“始终使用同一个任务”“依次观察这个请求怎样……”改为：

> 本章把 `parse_price()` 作为概念路标；各最小实验分别隔离观察 Token、注意力、采样与运行时边界，章末再把这些机制放回同一个 Coding Agent 任务。

第一章更强调机制隔离，方案 B 改动更小；若全书要强化“贯穿实验”的品牌感，则采用方案 A。

### 3. 残差连接段落把梯度方向写反

原文：

> 梯度可以沿着加法路径更直接地向前传播……

位置：`book/chapter1.md:530`。

梯度是在反向传播中从深层向浅层传递。“向前传播”通常表示激活从输入到输出的前向计算，容易让初学者建立错误概念。

#### 建议修改

改为：

> 在反向传播时，梯度可以沿残差的加法路径更直接地传向较浅层；在前向计算时，原表示也可以通过恒等路径继续保留。

这句话同时解释优化和信息保留，且不会混淆两个方向。

### 7. `parse_price()` 补丁比文字合同更宽松

候选实现使用：

```python
value.strip().replace("￥", "").replace("¥", "")
```

位置：`book/chapter1.md:1105`、`chapter1/coding_agent_demo.py:23`。

Docstring 说的是“可选的人民币符号”，案例描述说的是前缀，但 `replace()` 会删除字符串任意位置的符号。例如 `"1¥2"` 会被静默解析为 `12.0`。正文已经正确强调“两项测试通过不等于完整正确”，但这里可以提供一个更有教学价值的失败注入。

#### 建议修改

- 添加 `parse_price("1¥2")` 应失败的负例；
- 只移除首部的一个允许前缀，可使用 `removeprefix()` 或显式解析；
- 将这个案例写成“测试范围决定证明范围”的第二个失败样本。

### 8. 温度公式应明确限定 `T > 0`

公式位于 `book/chapter1.md:559`，后文又说明很多 API 会把温度 0 当成近确定性策略。数学公式在 `T=0` 时没有定义；第二章 `book/chapter2.md:412` 已经明确写出这一点，第一章应保持一致。

#### 建议修改

在公式后直接写：

> 上式只在 `T > 0` 时定义。工程接口中的 `temperature=0` 通常表示 greedy 或近确定性实现，不是把 0 直接代入公式。

### 9. “2000 个 Token 至少进行 2000 次连续采样步骤”需要更精确

位置：`book/chapter1.md:619`。

从概率分解看，2000 个输出位置确实具有顺序条件依赖；但 speculative decoding、多 Token prediction 或其他解码优化可能减少目标模型的串行前向调用次数。“采样步骤”如果被理解为“完整模型调用次数”，表述就过强。

#### 建议修改

改为：

> 生成 2000 个 Token 包含 2000 个有序的条件选择位置，因此输出长度通常显著影响延迟；推测解码等优化可以减少目标模型前向调用，但不会把自回归条件依赖变成完全独立的并行生成。

### 10. Bigram 的 `--steps` 容易被误解为训练步数

`bigram_lm.py` 没有梯度训练，`--steps` 实际表示最多生成多少个字符：

- `chapter1/bigram_lm.py:35`
- `chapter1/bigram_lm.py:54`

但文件 Docstring 使用“Train”，章节标题使用“拟合”，读者可能把命令中的 `--steps 120` 理解成优化步数。

#### 建议修改

- 将参数改名为 `--max-chars` 或 `--max-new-chars`；
- 输出中增加 `generation_limit`；
- 保留 `train()` 也可以，但正文应说明这里的“训练”只是计数估计，不存在反向传播与优化 step。
