日期：2026-09-10。范围：正文、7 幅在用图、5 组实验、14 题与答案、产品观察指南、来源及预览。由同一写作 Agent 自审，不冒充独立专家或真实读者试读。

## 读者视角

本章从“旧测试本来就是绿的”切入，在第一节完成相对路径、回归测试与一行修复。读者先看到问题和结果，再理解仓库环境、搜索、补丁、验收、指令、扩展和恢复。最终约 1.96 万中文字符、39 个二三级标题，未以术语清单替代连续讲解。

可取之处是每一项抽象机制能回到具体文件。例如摘要对应 linkcheck.py 是否被改，验收对应三项旧测试为什么漏检，恢复对应昨天的证据为什么不能用于今天。

仍有阅读成本：Git、摘要和独立验收对初学者是新概念。正文允许先运行 quickstart，再回读机制；产品配置与动手答案独立成文，避免主线变成安装手册。七张纵向图在手机中需要放大阅读小字，不应把无横向溢出当作所有图中文字在缩略尺寸都清晰。

## 技术视角：发现与处置

| 发现 | 处置与证据 |
| --- | --- |
| 固定修复序列可能被误认为模型独立诊断 | 正文、报告、README 均标明固定步骤；模型和产品成绩不填得分 |
| 源码摘要检查可能被夸大为并发保证 | 正文、工作台注释和图 11-4 明确检查与写入之间存在窗口，不是跨进程 compare-and-swap |
| 测试全绿可能掩盖覆盖不足 | 先记录旧测试通过，再加入回归产生失败；独立验收包含有效与缺失链接 |
| “冻结测试”可能被误解为不允许补测试 | repair 在追加已公开回归之后、改源码之前冻结；答案明确批准新预期与防篡改的区别 |
| 恢复可能混淆会话与文件回滚 | 旧回执保持历史结果；当前文件摘要另行核对；产品恢复范围引用官方来源 |
| 初稿图中出现“无新增问题” | 图 11-1 改为“已覆盖场景通过”，旧图保留但不再引用 |
| 搜索图生成了不属于本实验的代码和错误目录 | 图 11-3 经两轮修订，使用真实符号、代码、命令与正确目录 |
| Hook 图混入提交、推送和合并检查 | 图 11-6 改用工具前后及一轮结束事件，并限定产品支持范围 |
| 教学 Markdown 链接被静态检查当成正文导航 | 示例围栏显式标注 invalid-example；预览编码代码块方括号，视觉保持原样 |
| 双词围栏信息在可选渲染器中未被识别 | 改成受支持的单一围栏标签；新增预览断言，防止原始围栏混入正文 |
