# 第 12 章审稿报告：v1.0-rc1

审稿对象：`book/chapter12.md`。审稿日期：2026-09-20。结论：**候选稿可以进入插图与预览阶段，但不能标记为已发布或全部验收完成。**

本轮同时采用新读者视角和工程视角。正文经过审读后已修改；下面记录发现、改动和仍未解决的限制，避免把“作者解释得通”误当成“读者一定读得懂”，也避免把代码测试通过误当成运行环境已经安全。

## 新读者视角

### 读者能够抓住的主线

开头使用同一个 Markdown 链接修复贯穿全章，先展示短轨迹，再解释协议、工具、审批、恢复与验证。这个顺序比从 framework API 或抽象状态机切入更容易建立直觉。正文还用“新员工入职”解释模型、权限、执行和验收的关系，用快递单号与包裹指纹区分 `call_id` 和 `action_id`，对第一次接触 Agent 工程的读者友好。

五组实验都回答一个具体问题，而且每组都写明“不证明什么”。练习从工具提议逐步走到 approval、sandbox、LangGraph 和 Agents SDK，难度梯度基本合理；14 道答案都有可运行入口，不是只给概念问答。

### 发现的问题与已修改内容

1. 初稿前半段术语密度偏高，读者可能在还没看见一次完整运行前就遇到 Harness、Verifier、receipt 等词。已修改为先给短轨迹和生活类比，再引入术语；同一概念第一次出现时同时说明它“不负责什么”。
2. 初稿对 Replay 的边界虽然正确，但不够突出“哪些是真执行、哪个是假决策”。已修改为四层证据模型，明确文件、测试、SQLite 和真实 framework 会运行，只有模型决策固定；真实模型仍是 0 请求。
3. 工具协议容易被读成 API 字段清单。已增加“每个错误对应什么下一步”、新增工具检查表、读写工具的失败例子，让代码字段回到实际问题。
4. 初稿结尾错误地衔接到 Multi-Agent，与 `book/OUTLINE.md` 不一致。已修改为衔接第 13 章“Agent 评估：答案正确还不够”，并说明本章证据怎样进入下一章任务集和评分器。
5. 来源编号原先是孤立的 `[PI-...]` 文本，视觉上像失效脚注。已修改为指向 `book/sources/chapter12-sources.md` 对应锚点的可点击链接。

### 新读者仍可能卡住的地方

审批恢复和三态幂等是全章认知负担最高的部分。正文已经加入时间线制图标记和 before / after / current 表，但正式图片尚未制作；Task 15 应优先完成图 12-4。框架重构部分没有逐行讲两个适配器，这是有意控制篇幅：正文解释责任迁移，完整实现留给配套代码。预览时应检查代码链接是否容易打开。

## 工程视角

### 已核对的事实

- 五工具名称、调用结构和结果结构与 `chapter12/contracts.py` 一致。
- 路径、唯一匹配、文件版本、全工作区 manifest 与写入边界与 `chapter12/tools.py` 一致。
- decide → propose → execute → observe → verify 的描述与 `chapter12/runtime.py`、`services.py` 一致。
- completion 由宿主 Verifier 决定；final text、SDK `final_output` 和测试日志都没有被写成完成证据。
- approval 绑定、写后未回执恢复、第三态停止与 `chapter12/recovery.py` 和持久账本语义一致。
- LangGraph 的 interrupt 重入、Agents SDK 的 RunState / native approval 都按锁定版本说明，没有把 framework checkpoint 写成唯一可信状态。
- Pi 固定在提交 `19451accdeec671c1f4da9eafac8fc270f510ef4`，正文明确“源码阅读，不是产品运行记录”。

### 工程问题与已修改内容

1. `returncode=0` 容易被误读为测试完成。正文已增加 discovered、truncated、cancelled、timed_out 和结构诊断条件，并解释零项测试假绿。
2. “策略、审批、sandbox”容易混为一层。正文已把控制平面和强制执行平面拆开，明确路径白名单与用户批准不能证明网络、身份和资源隔离。
3. “幂等”原先可能被简化成重复写相同内容。正文已增加外部 API 幂等键示例，并说明相同字节写两次仍可能覆盖用户编辑。
4. 上下文压缩可能被理解为覆盖历史。正文已补充三层上下文和事实过期问题，说明完整 Trace 与权威 state 不被摘要替换。
5. 框架比较容易被读成排名。正文与实验都固定任务、决策、工具和 Verifier，只比较编排责任；明确一份 fixture 不能比较模型或框架质量。

## 残留限制

1. 七幅图仍是制作标记，尚未做视觉审稿、移动端字号检查和图文重复度检查。
2. 容器运行时按用户决定暂不安装，sandbox 的非 root、只读根、禁网、资源限制和取消清理仍未验证；正文不得改写为已通过。
3. 真实模型运行未执行，不能评价模型自主修复能力、成本、延迟或真实工具选择质量。
4. Windows 符号链接测试因本机权限跳过；已有 Linux 路径探针不等于完整容器隔离。
5. 验收 runner 能发现教学误修和明显伪造，但在 trusted-local 同进程模型下不抵抗主动恶意代码；敌对代码仍依赖尚未补齐的强制隔离。
