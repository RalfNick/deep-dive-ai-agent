- Review 日期：2026-09-01

## 总体结论

整改后的章节约 2.55 万个有效中文字符，以同一个虚构支付故障任务贯穿 v0–v6。主线从“文本误报完成”开始，依次增加 JSON、Schema、四份合同、Tool Loop、授权与 Receipt，最后接入官方 MCP Python SDK。读者不需要 API Key 就能重现实验，代码、报告、Trace、练习和图片能够互相指向。

综合评价为 9/10。最强的部分是边界意识和证据链：模型提议不等于执行、Host 同意不等于 Server 授权、Tool Result 不等于可信 Receipt、进程内 SDK 测试不等于真实网络兼容。初稿的主要问题不是内容不足，而是三处表述或视觉可能把教学简化误认为协议事实；现已全部整改并增加回归检查。

“可进入发布接入”只表示本章满足当前书稿合同，不表示示例已经达到生产级。持久幂等、远程 OAuth、真实传输故障、大规模工具发现和模型统计评估仍是公开限制。

## 读者视角 Review

开场对非 SRE 读者友好。正文在第一次使用时解释“值班”“P1”“Runbook”，并用“模型声称已建单、系统列表仍为空”制造可验证冲突。支付故障只是稳定的实验载体，不要求读者理解复杂运维体系。

章节路径清晰。v0–v4 均使用“输入—关键代码—运行结果—解决了什么—还没有解决什么”的固定节奏；每个版本只新增一类边界。代码片段保持一屏内可读，完整实现留在 `chapter9/`。v5–v6 再引入 MCP，避免读者把协议、执行器和 Agent Loop 混成一个黑盒。

初稿最明显的可读性问题是短答案表格一次引入多个英文合同名。新增的单据类比把四个对象放回日常经验：目录、申请、结果和关联回执。类比没有替代精确定义，后文代码仍逐一展开字段和责任。

输出解释充分。每条运行命令后都说明应该看到的状态、副作用数和未发生的动作；规范报告另有可读 Markdown。没有用“运行成功”替代验收，也没有要求初学者从整段 JSON 自己猜结论。

唯一仍需读者投入较多精力的部分是“从教学实现走向生产”与失败注入推演。这些内容放在主线之后，并使用粗体段落而非继续增加标题，作为进阶阅读是合理的。快速入门读者可以先完成 v0–v6 和一星练习，再回看生产部分。

## AI 工程视角 Review

**协议版本。** 现代 MCP 基线明确写为 `2026-07-28`，旧版兼容路径明确写为 `2025-11-25`。正文准确区分每请求自描述、可选 `server/discover` 与旧版初始化握手，也明确“无协议 Session 不等于业务无状态”。

**SDK API。** 配套代码锁定 `mcp==2.1.1`，使用官方 `MCPServer` 与 `Client`。默认 Client 验证现代版本，`mode="legacy"` 验证显式旧版路径。进程内测试经过官方 SDK，而不是自制相似 JSON；正文同时拒绝把它推广为 stdio、HTTP 或任意第三方实现兼容。

**Schema。** `schema.py` 明确只实现 `type`、`properties`、`required`、`additionalProperties`、`items`、`enum`、`minimum`、`maximum` 八个关键字，并拒绝未知关键字。正文没有把它包装成完整 JSON Schema 2020-12，生产建议指向成熟实现。

**错误语义。** 应用内 `ResultStatus` 保持小而稳定，`failure.code` 保存细分原因；整改后正文明确它不是 MCP Wire Error 枚举。Unknown Tool、畸形协议请求与 Tool Execution Error 的区别已写入正文、README 和来源用途。

**同意与授权。** Host 负责用户意图、展示和同意，Server 根据受信身份与 Scope 做业务授权。模型 Arguments 不承载 `approved`、角色或 Token。读 Tool 自动 `allow` 已标注为预先同意的教学假设，避免把 Fixture 策略误写成规范通行证。

**Receipt 信任。** Receipt 只能由执行边界在 Handler 成功并返回外部 ID 后构造，模型伪造字段在封闭 Schema 门被拒绝。整改后不再暗示其为独立密码学证明；跨服务生产方案需要回查、签名或独立 Verifier。

**传输与安全。** stdio、Streamable HTTP 与直接函数调用按部署和信任边界选择；正文没有宣称 stdio 天然安全。威胁模型覆盖恶意 Server、Resource/Result 注入、路径越界、Token 透传、confused deputy、日志泄露和供应链变化。

**Provider 与框架映射。** OpenAI Responses 的 JSON 字符串 Arguments 与 Anthropic `tool_use.input` 对象通过 Adapter 归一；默认实验不联网。LangChain 与 LangGraph 只映射它们替代的样板代码，业务授权、完成证据和审计仍归应用所有。

**章节边界。** 本章只为超时、重试、取消、异步与大规模发现建立接口地图；实现细节留给第 10 章。Claude Code、Codex 等产品级 Harness 留给第 11 章。没有提前把后续两章写完。

## 视觉 Review

8 幅 PNG 使用统一的中文手绘教学风：奶油纸张、深蓝线条、低饱和蓝绿紫橙、明确编号和底部结论。主图为 1024×1536，其余为 1536×864。每幅图在正文中只有一次引用，并带独立替代文本、“读图顺序”和“这张图要说明”。

视觉不是正文表格的截图：主图承担端到端旅程，边界图解释三层关系，四份合同图解释对象责任，Loop 图解释结果回流，MCP 架构图解释隔离，三原语图解释控制权，协议图解释时序，失败地图解释多道门禁。

失败地图 v1 的最右端语义错误已通过重新生成解决，未使用程序覆盖文字。v2 提示词与最终图片均保留；图像测试检查 v2 提示词必须以“继续 / 停止”结束。生成模型仍可能产生肉眼才可见的细小笔画差异，因此出版前应继续进行人工视觉抽检。

## 未接受的建议及理由

**把教学 `ResultStatus` 扩展成完整 MCP 线上错误枚举。** 未接受。核心 Runtime 是 Provider/MCP 中立的教学边界，线上协议错误由 MCP Adapter 与 SDK 处理。增加完整枚举会让 v2 提前承担协议细节；正文已明确两套分类不可一一对应。

**把真实 Provider 调用设为必跑主实验。** 未接受。主实验要固定决策以验证外围边界；实时 Provider 会混入模型、网络和版本变量。可选 Live Probe 已足以演示 Adapter 形态，且默认离线。

**本章实现完整 OAuth、Streamable HTTP 与持久幂等。** 未接受。它会把第 9 章扩成生产平台章节，并与第 10 章重复。本章保留威胁与接口地图，公开未实现范围。

**每个读 Tool 都弹出一次确认框。** 未作为固定 UI 规则接受。协议强调人类可控制和拒绝，但不强制一种界面；低风险读取可以在清晰展示范围后使用有时限、按资源裁剪的预先同意。高风险与敏感数据仍需要更细确认。

**给教学 Receipt 加密码学签名。** 未接受。当前 Handler 与 TicketStore 同处一个进程，签名不会增加实验要验证的边界。正文改为准确说明证据强度，并把跨服务签名与回查列为生产方案。

## 最终剩余风险

- `TicketStore`、Call ID 去重和 Grant 都是进程内状态，进程退出后不持久。
- 官方 SDK 进程内测试没有覆盖真实 stdio 子进程、Streamable HTTP、代理、OAuth 和网络分区。
- 教学 Schema 子集不覆盖组合 Schema、引用、格式、完整 Unicode 和官方测试套件。
- Live Probe 是可选单次观察，不提供模型质量统计，也未纳入规范报告。
- 图片中文字由生成模型绘制，机器测试只验证尺寸、引用和提示词语义，最终出版仍需人工目视。
- MCP、Provider 与框架接口会演进，出版前必须按来源台账再次复核。

以上风险均已在正文或读者资料中公开，不构成未处理的 P0/P1，但会限制读者把示例直接复制到生产环境。
