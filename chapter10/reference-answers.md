# 第 10 章分层练习参考答案

对应[正文末尾 14 题](../book/chapter10.md)。代码均在仓库根目录运行，使用标准库；不要先修改规范报告使其看起来通过。

## 1. 三个集合

不能。300 是注册目录；299 是经过当前发现权限过滤后可以找到的定义；2 是本轮加载量。用户可能有权使用许多尚未加载的工具，也可能在加载之后失去权限。调用时必须以当前身份、工具版本与对象级权限为准。

“模型没有看到”不等于“用户没有权限”，“模型曾经看到”也不等于“用户现在仍有权限”。两句都要解释，才算完整。

## 2. 手算分数与歧义

先过滤退款工具，不对它评分。订单得 3 分，物流得 2 分。查询只有“状态”时，两者都得 1 分。按名称排序只是稳定输出，不是语义裁决；可利用前文消歧，缺少信息时询问用户想查支付还是物流。

如果有退款权限，也不能因为它出现在相关候选中就执行。请求规则、查询状态和发起退款是不同意图。

## 3. 字节口径

`150 + 452 + 810 = 1,412` 字节。需要包括常驻入口和候选摘要，不能只计 810。这里测的是规范化 JSON 的 UTF-8 编码长度；Tokenizer 词表、消息包装和提供方缓存均不由这个数字确定。真实 Token 与费用必须从匹配版本的计数器或 API usage 取得，不能除以某个固定常数后当作精确结论。

## 4. 理想等待时间

忽略所有开销与抖动，串行 600 毫秒；并发上限 2，分两批，400 毫秒；上限 3，一批，200 毫秒。题目假定相互独立且每次恰好 200 毫秒。实验实际只用屏障证明两个读取重叠及峰值约束，没有连接真实网络，也没有测量这些时长。

## 5. 识别意图还是识别工作

提交键在创建作业前就由调用方保存，响应丢失时可复用；作业号由系统创建后返回，用于查询被接受的工作。每次重试换键，系统只能把每次视为新意图。

作业重试时保持作业号、递增尝试代次。重新导出一份新的报表属于新意图，应换提交键。相同参数并不必然代表相同意图。

## 7. 预算边界

```powershell
python -m unittest chapter10.tests.test_exercise_solutions.ExerciseSolutions.test_exercise7_exact_budget -v
```

先加载一次并用同一个 `byte_size()` 取得准确长度 `n`；预算 `n` 时返回完整原对象，预算 `n-1` 时抛出异常。函数在返回前检查整批大小，因此不会返回部分列表或残缺 JSON。不要用肉眼数字替换序列化长度，也不要拿字符数与字节预算比较。

## 8. 五个调用、一个失败

```powershell
python -m unittest chapter10.tests.test_exercise_solutions.AsyncExerciseSolutions.test_exercise8_five_calls_one_failure -v
python -m unittest chapter10.tests.test_concurrency.ConcurrencyTests.test_cancellation_propagates_and_workers_exit -v
```

五个 ID 为 `0`–`4`，第三个参数对应的 ID `3` 返回 `LookupError`，其余四个保留值；用屏障与活动计数确认峰值为 2。外层取消测试检查 `CancelledError` 传播，并确认 worker 的 `finally` 已执行。

仅有“最后返回五个元素”不能证明关联正确，也不能证明并发没有越界。仅有“取消函数返回了”不能证明内部工作已收束。

## 9. 加一条记录

## 10. 租约与旧代次

领取时刻为 1、租约长度为 2，`lease_until=3`。系统使用大于等于到期判断，因此时刻 3 无论有没有新 worker，旧领取都已失效。尚未重新领取时返回 `lease_expired`；新 worker 已领取并使代次递增后，旧 worker 返回 `stale_attempt`。

```powershell
python -m unittest chapter10.tests.test_jobs.JobTests.test_expired_worker_cannot_finish_before_reclaim -v
python -m unittest chapter10.tests.test_jobs.JobTests.test_lease_recovery_fences_old_worker -v
```

两条测试不能互相替代。只检查当前代次，会漏掉“租约过期但尚未被重新领取”的窗口。

## 11. 两个连接竞争

```powershell
python -m unittest chapter10.tests.test_jobs.JobTests.test_two_connections_race_for_one_lease -v
```

参考测试用两个线程，各自创建独立 SQLite 连接，并通过屏障一起尝试领取。结果集合中应恰好有一个代次 1 和一个空值；不是两个都成功，也不是两个都失败。时刻 11 租约到期后，主连接可取得代次 2。

这里检验的是本地 SQLite 写事务的互斥领取，不是跨数据中心分布式队列性能。真实多连接竞争比在一个字典上顺序调用两次更有说服力。

## 12. 报表后发邮件

本地唯一约束约束不了远程邮件系统。邮件已经发出、进程在本地落账前崩溃时，重新执行可能发出第二封。

一种方案是邮件服务提供业务幂等键与状态查询：以稳定的发送意图键创建发送请求，超时后先查询该键对应状态，同键重试由服务端返回既有结果。必须验证服务端保留窗口、同键参数冲突及副作用原子性，不能只确认 SDK 能传一个自定义 header。

若邮件服务没有幂等、没有可靠查询，遇到结果未知应进入待确认流程，暂停自动重发，保留外部请求号与脱敏证据，交给人工核对。若业务宁可重复也不能漏发，需要由业务方明确接受这种语义，并在产品上提示；这不是 exactly-once。

评分看是否识别“响应丢失≠未发送”、是否说明谁执行幂等、是否处理未知结果，而不是看是否写出了 outbox 这个词。

## 13. 可恢复进度页面

提交前在客户端保存意图键；收到回执后保存作业号。页面进入时按当前身份查询作业状态，不能把浏览器缓存里的 `running` 当作事实。事件处理成功后保存游标，补读时按事件 ID 去重；最终终态以作业状态接口为准。

停止页面等待只结束本次查询，展示“稍后可继续查看”；取消按钮调用取消接口，先显示“已请求取消”，查询到 `cancelled` 才显示“已取消”。若已经成功，应展示已有结果，不能把结果隐藏后谎称取消完成。失败时展示经过脱敏的错误码与是否允许重新发起。

下载结果必须再次授权，结果标签与临时 URL 不取代身份。进度未知时显示阶段，不虚构百分比；一次尝试重启时区分代次。用户刷新页面、换设备、失去权限、结果过期，都应有明确处理。

## 14. 多租户容量与观测

先按租户/身份过滤目录，再检索与加载。候选数取决于任务覆盖实验，不能只为了最小上下文把所需能力挤掉。分开设置全局与租户并发配额、请求速率和有限队列，记录拒绝并向调用者提供退避建议。接受重复意图不应再次消耗容量。

幂等记录至少覆盖允许的重试和故障恢复窗口；结果保留时间可以不同，但结果删除后同键再来应返回什么必须事先定义。外部服务的幂等键过期时间也要纳入设计。

至少六项指标的合格示例：

| 指标 | 定位用途 |
| --- | --- |
| 正确工具进入候选集的比例 | 区分发现遗漏与模型调用错误，需要独立标注查询集 |
| 无权限候选泄露数 | 检查过滤次序和缓存隔离 |
| 每任务搜索轮数与实际 usage | 判断减少定义是否被额外往返抵消 |
| 队列等待分位数及每租户占用 | 识别饥饿、容量瓶颈和资源不公平 |
| 峰值在途与限流/拒绝数 | 判断下游压力与入口背压 |
| 重复意图数、实际重复副作用数 | 区分重试流量与幂等失效 |
| 过期租约回收数、迟到提交拒绝数 | 判断 worker 停顿或租约设置过短 |
| 取消请求到终态的时长 | 找到缺少检查点或不可中断的执行 |
| 结果待确认数与积压时间 | 防止未知外部状态被隐藏 |

这些是应采集的指标，不是本章已测出的生产数值。评分重点是各指标能否指向一个明确机制，以及方案是否说明成本、安全与容量之间的取舍。
